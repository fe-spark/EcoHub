预发布版 **v3.0.0-beta.17**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v3.0.0-beta.17`。不会覆盖 `latest`。

### 升级指引

- **试用本版**：把 Compose 镜像版本指定为 `ghcr.io/fe-spark/ecohub:v3.0.0-beta.17`，然后执行 `docker compose pull ecohub && docker compose up -d ecohub`。
- **破坏性变更与数据兼容**：**不兼容，不迁移。** 本版本为 v3.0 重大架构重构版本，完全不向后兼容 v2.x 历史数据。已入库的播放列表也不会改写；重复选集要重新采集对应站点才会拆开。请勿直接挂载 v2.x 历史数据库升级。

---

### v3.0.0-beta.17 核心变更

- **彻底修复停止采集时主站阻塞卡死（90秒无响应）缺陷**：
  - 采集任务退出清理时增加终态拦截，任务被取消或处于终止态时严格跳过主站 `finalizePrimarySource`，秒级退出不再阻塞；
  - 播放线路加载查询 `loadPlaySources` 接入严格的 500 条分批查询，彻底根除 MySQL 占位符溢出异常（Error 1390）。
- **超大规模与全量采集大批量变更智能转全量重建并广播进度**：
  - 增量重封口函数接入阈值控制（`maxIncrementalMids = 1000`），超过 1000 部影片的大批量写入不再执行成千上万次单次 SQL 循环，自动无缝切换为后台单次流式全量重建；
  - 重建过程实时通过 SSE 事件向前端分批广播 `search_index_progress`（如 10%、20%...100%），前端队列条平滑展现「收尾中 · 检索索引进度」；
  - 限制批次上下文全局 MID 内存暂存上限（1500），杜绝全量采集时上百万个 MID 堆积造成的内存膨胀。
- **采集中心页面刷新后停止状态自愈与维持**：
  - 队列进度条组件全面对齐 `isStopping` 状态，页面刷新后若队列中仍有站点处于停止中，终止按钮立即呈现 Loading 状态；
  - 刷新页面时自动在内存中重建未决终止队列映射，全站终态落地后平滑触发「采集已终止」通知与进度清理；
  - 站点卡片网关活跃判断接入 `isCollectBusyStatus`，刷新后卡片完整保持停止中高亮与操作禁用。
- **前台播放与后台用户交互空值容错加固**：
  - 播放页背景海报增加空地址保护，规避动态无图时渲染空标签；
  - 影视抽屉封面预览增加缺省占位图兜底；
  - 顶部导航栏与用户管理列表头像增加空白字符串修剪与防空防护。
