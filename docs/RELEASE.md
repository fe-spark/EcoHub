### 升级

- v3.0.x：`ecohub` 安装的执行 `ecohub update`。1Panel 或自建 compose 在安装目录执行 `docker compose pull && docker compose up -d`。
- **v3.0.3 不再读取 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`**：编排和 `.env.example` 删掉了这三个变量，旧 `.env` 里留着也不会生效。之前靠它们让弹幕或 Telegram 走代理的，升级后到后台「网络代理」开启全局代理，并打开「弹幕抓取」或「Telegram 机器人」模块，否则这两项会直连。
- v2.x：不兼容，不迁移。见 [从 v2 升级到 v3](https://github.com/fe-spark/EcoHub/blob/main/docs/v2-to-v3.md)。

### v3.0.3 修复

- **网络代理**：弹幕抓取和 Telegram 通知改为只看后台「网络代理」：全局代理开启且对应模块（「弹幕抓取」「Telegram 机器人」）开启时走代理，否则直连。「弹幕抓取」是新模块，默认关闭。
- **弹幕加载状态**：不再用提示盖在画面上，结果写在弹幕输入框的灰字里，左侧圆点表示加载中、正常、没有全网弹幕或失败，悬停看完整说明和失败原因。播放器宽度小于 `560px` 时输入框收起，圆点显示在弹幕开关上。
- **弹幕测试**：「网站配置」的弹幕卡片在开启「自动嗅探全网弹幕」后多一个「测试」按钮，用当前填写的配置拉一部片第 1 集的全网弹幕，结果显示在按钮下面；同时显示弹幕请求走代理还是直连。
- **播放器弹幕**：改回弹幕插件自带的调度，补丁只保留装载提速（#63）和时间为 0 的弹幕不再被挪后。开关、透明度、字号、速度、显示区域、弹幕类型、防重叠存在浏览器里，换集后保留。修复手机上看不到弹幕开关和设置（#83）。
- **播放器按宽度排版**：按播放器自身宽度而不是设备类型排版，窗口变窄立即切换。小于 `560px` 收起弹幕输入框和网页全屏按钮；`560–767px` 收起网页全屏按钮；`768px` 起完整布局。弹幕字号随播放器宽度缩小（最小 `12px`），显示区域按画面算，不再飘到黑边上；宽度小于 `768px` 时顶部、底部弹幕按滚动显示，手机上弹幕不再互相重叠。
- **播放器边框**：所有宽度都有 1px 边框和圆角，手机深色背景下也能看清播放器范围。全屏和网页全屏不带边框。
- **播放区高度**：页面单列（宽度不超过 `1024px`）时，播放区高度按视频真实宽高比撑满宽度，没有多余的上下黑边。竖屏视频最高占屏幕 75%，超宽视频最低 `180px`。弹幕设置面板放不下时在面板里滚动。
- **选集面板**：页面单列时选集面板随内容撑开，列表最高 `max(320px, 60svh)`，不再只露一两行。超过 100 集时按 50 集分段（1-50、51-100…），默认打开正在播放的那段。
- **TVBox 年份排序**：同一年的片子再按更新时间排，与前台一致。
- **安装脚本**：`ecohub` 支持安装目录里自己写的 `docker-compose.override.yml`，安装和更新不会覆盖它，所有 compose 命令都会叠加它。`ecohub help` 补上 `SERVER_PORT`、`MYSQL_ROOT_PASSWORD`。
- **文档**：按新的写作规范重写全部文档，并按代码改正错误；部署、常见问题、服务端、前端、v2 升级、计划任务冲突和版本说明都有英文版。

### 架构

- 取消主从绑定。各采集站独立建档，单站异常不影响其他站。
- 启用站里排序第一的是前台主站。切换立刻换成该站已有数据，不重采、不删片；轮播按站点分开存，首页展示新主站自己那组。
- 播放页按匹配键附上其他站线路：豆瓣 ID + 片名，片名#分类，纯片名。线路按站分开，不合并档案。
- 结构迁移只留空基线，新变更只在末尾追加。

### 采集

- 去掉请求间隔和写库令牌桶。全局在途 128，单站 16 个协程，单页写事务 30 秒超时。
- 零成功且取页失败达阈值才熔断。已有成功页的站连续失败 20 页暂停 5 分钟续采，连续暂停 3 次仍失败结束本轮。停止或导入时丢掉未开写的页，写完已经打开的事务。
- JSON 探页用 `detail`，XML 探页用 `videolist`，与正式抓页一致。
- 定时采集碰到维护会让行，之后按未采窗口补，最多 7 天。只有定时整次成功才移动补窗锚点。规则见 [计划任务冲突](https://github.com/fe-spark/EcoHub/blob/main/docs/cron-task-conflict.md)。
- 批次记在 `collect_records`，入库明细记在 `collect_record_films`。状态按实际落库：成功、部分成功、失败、已停止、异常中断。没抓的页写明未抓。
- 30 分钟内重试失败页，超时则整站重采。成功批次归档，历史记录定时清理。
- 未映射影片归入该站一级「其他」（源站「其它」视为同一类）。隐藏或停用的分类（含「其他」）仍正常采集入库，前台不展示。有成功页仍进入待检索；零成功直接失败。
- 封口期间不能删站，也不能改地址或协议。删站只等一次检索收尾。
- 可用内存不超过 2GiB 时，只收紧页并发、取数在途和写队列。

### 检索与前台

- 内存倒排（分词、全拼、简拼）和分类榜。采集增量更新。启动时全量重建一次；增量更新时内存里没有可用索引或读库失败，也会补做一次全量重建。
- 首页隐藏没有影片的分类，分类区块最多 12 个一级分类。导航、筛选和 TVBox 仍用该站全部分类。
- 分类规则按站生效。前台分类的排序和显示跟随管理端映射。隐藏分类（含规则合并组）从前台所有接口消失，旧地址显示分类已失效；搜索、每日更新和 TVBox 关键词也不返回这些片子。采集仍把这些片子入库。分类管理仍可看到并重新打开。子类不会自己变成一级。
- 未映射片子出现在该站「其他」。源站改名占用旧「其他」编号时，兜底换新编号。
- 播放器支持多线路、进度记忆和弹幕。更换弹幕源后不命中旧缓存。
- **图片加速**：开启媒体反代时，前台与 TVBox 海报自动走边缘 CDN，免代理直开且不消耗自建带宽。

### 后台

- 操作改为抽屉。配置、站点和规则可备份导入，导入前会停采集。
- **轮播**：按站点存储，片名、分类、备注等跟随片库实时组装；该站已无播放线路的影片首页不展示，后台标为已失效，可删除和排序。手动增删改排序有版本号校验，并发修改会提示刷新。
- **一键排片**：选策略（最新、最热、高分）和各分类数量，每个分类最多 5 部，不限总数；结果在抽屉里预览、调整后整组发布。排片配置不入库，每次一键排片都弹窗确认，默认最热、每类 1 部；同一页面内再次排片沿用该站上次的选择，刷新后回到默认。
- 分类管理与前台共用同一套规则树，只调整排序和显示。父级隐藏时子类开关不可改。
- 角色为超级用户、普通用户、访客。
- 影片列表的 ID 列是源站编号。采集中的失败页只把失败数标红。
- 单条坏线路只跳过该线路。配置已经落库后，缓存写失败会删掉旧值。
- **媒体反代**：支持边缘反代模板配置与校验，服务端出站动态替换海报地址，不污染原数据。
