正式版 **v2.2.4**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.2.4` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **从 v2.1.x / v2.2.x 升级**：执行 `docker compose pull && docker compose up -d` 即可（或后台「检查更新」一键平滑升级）。
- **从 v2.1.0 之前升级**：请先按 [v2.1.0 说明](https://github.com/fe-spark/EcoHub/releases/tag/v2.1.0) 完成素材卷目录迁移，再升级到本版本。

---

### v2.2.4 核心变更

#### 1. 采集失败记录管理深度重构与批量重试
- **行级内联状态交互与防重保护**：移除顶部全局进度条，重构为表格每行独立展示「重试中」加载动效与清晰状态标签；重试过程中严格禁用操作按钮与勾选框，避免并发重复触发。
- **支持多选与批量重试**：新增记录多选功能，支持一键「重试选中项 (N)」，便于快速恢复指定批次的采集失败项。
- **操作语义升级与高危防护**：重构操作按钮为「重试全部待处理」、「清理已完结记录」（安全清理已成功和已超限失败的归档，保留待重试项）与「清空全部记录」（高危操作二次确认防护）。

#### 2. 重试状态机闭环与历史脏数据自愈
- **状态机硬约束**：明确 0/5 到 5/5 递增计次，状态严格受约束保护：重试不满 5 次强制保持「待自动重试」状态，满 5 次才转为「最终失败」，重试成功即时清理/更新为「重试成功」。
- **历史脏数据自动纠偏自愈**：后端在列表分页查询与服务启动时自动检测并纠偏历史数据中状态与重试次数不一致的异常数据，无需人工修复。
- **修复全量待重试检索缺陷**：修复全量重试时因单页查询限制导致的遗漏待重试记录问题。

#### 3. 分页体验优化与防闪烁
- **分页状态保持**：修复失败记录页面高频轮询刷新导致的界面闪烁及批量操作时强制重置到第一页的问题，平滑保持用户当前浏览分页上下文。

#### 4. 内存搜索索引并发稳定性升级
- **atomic.Pointer 架构升级**：主站切换与全量收尾发布时，内存搜索读模型与全内存索引全面升级为泛型 `atomic.Pointer` 架构，杜绝空指针异常与并发读写冲突，实现零停机平滑热切换。

#### 5. 在线升级仅超级管理员可检测与执行
- 后台「立即升级并重启」与升级 API 仅超级管理员可用；普通用户 / 访客登录不检测 GitHub 更新，也不返回升级过程状态。
