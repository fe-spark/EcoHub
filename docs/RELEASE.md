正式版 **v2.6.8**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.6.8` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **平滑升级**：支持后台「检查更新」一键平滑升级，或通过 `docker compose pull ecohub && docker compose up -d ecohub` 快速更新。
- **数据兼容**：无需改表。`mid` 仍是主站 `vod_id`；匹配键继续用片名#大类隔离同名跨类。旧键上能唯一对上一部影片的附属站播放列表，用一次性脚本归并（先 `--dry-run`），同名跨类不会被合并：

```bash
docker exec -it ecohub /app/migrate_slave_playlist_keys --dry-run
docker exec -it ecohub /app/migrate_slave_playlist_keys
```

- **追集修复生效**：升级后对附属采集站再跑一轮采集。片名只对上一部主站影片时（副站大类标错也算），播放列表写到该片主键，详情页才能看到最新集。

### v2.6.8 核心变更

- **同名跨类仍隔离**：分类不编进 `mid`；匹配键带大类，避免「仙逆」短剧（已完结）的集数盖住「仙逆」动漫（连载），每日更新漏更。
- **副站追集主键对齐**：附属站唯一命中一部主站影片时，播放列表写到该片已有主键；副站把动漫标成电视剧这类乱标，只要片名只对上一部，同样写到该片主键。同名跨类（两个仙逆）仍隔离。采集顺序无限制。
- **采集写入不再整组删除**：附属站播放列表按 `(source_id, movie_key, group_index)` 原地更新，只删消失的线路，避免多源同时写同一主键时互相堵住。
- **播放源仍按站点隔离**：附属站剧集按 `source_id` 分列，不会写进主站「默认源」。
- **详情展示最新附属源**：同一采集站若因匹配键留下多份播放列表，详情页使用该站自己集数最多的一份；附属站写入只要播放列表有变化就会刷新详情缓存，不再要求超过全库最大集数。
- **停止采集不再卡住**：停止任务会取消 HTTP 请求与写队列，其它源可以继续收尾。
- **采集站数量上限改为警告**：取消 12 个硬限制（新增与备份导入均不再拦截）。超过建议数量时弹窗提示：采集站越多，排队越长，写库、快照和内存占用都会上升，低配机器更容易打满。
