### v2.6.0-beta.4 核心变更

#### 1. Telegram Bot 交互式分类与分页查阅
- 引入 Telegram Bot 长轮询引擎与内联交互键盘，采集批量更新后支持直接在聊天窗口中按大类（电影、电视剧、综艺、动漫等）过滤并分页翻页；
- 采用 Redis 48h TTL 会话缓存与本地内存淘汰容灾，基于轻量短编码回调机制解决 Telegram 64 字节 callback_data 限制；
- 增加针对 HTML 实体特殊字符（如 `&`、`<`、`>`）的转义安全保护，以及返回分类消息超长时的自动安全截断。

#### 2. 分布式锁防脑裂与异步高并发加固
- 重构 Bot 轮询选主逻辑：仅在单机部署（无 Redis）时退化为本地抢占，集群环境 Redis 出现超时或通信异常时采用 Fail-Closed 机制保持待命，杜绝并发拉取 updates 导致的 Telegram 409 conflict；
- 将内联键盘按钮回调（`CallbackQuery`）派发至独立协程异步处理，并挂载全局 `recover()` 防崩溃保护，避免网络或 DB 查询阻塞轮询主协程；
- 优化分页切片性能，消除对全量变更项频繁构建映射的高内存与 GC 开销。

#### 3. 访问日志过滤精细化与空数据库保护
- 调整访问日志过滤策略（`ShouldSkip`），仅过滤探活与静态图片，保留后台管理接口及日常接口访问日志输出，消除运维审计盲区；
- 修复无数据库连接或初始化过程中的 `GetSiteBasic()` 空指针隐患；服务优雅停机时联动关闭轮询器并安全释放锁。

#### 4. 质量与回归验证
- **全仓测试**：Go 后端全模块单元测试 100% 通过（含新增轮询生命周期、HTML 转义及会话淘汰单测）；
- **前端检查**：Next.js `npx tsc --noEmit` 0 错误。
