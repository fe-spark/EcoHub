测试版 **v2.5.7-beta.0**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.5.7-beta.0`。

### 升级指引

- **从已有版本升级**：
  - **1Panel / Compose**：执行 `docker compose pull ecohub && docker compose up -d ecohub` 即可（或后台「检查更新」一键平滑升级）。
  - **数据迁移与平滑割接**：启动时自动执行 GORM AutoMigrate 新建 `slave_movie_playlists` 表，并在分布式锁保护下将老表中存量附属站播放列表全自动平滑割接至新表，无需手动执行任何 SQL 脚本。
  - **兼容性说明**：本版本完全向下兼容现有 MySQL 与 Redis 数据结构，无破坏性变更。

### v2.5.7-beta.0 核心变更

#### 1. 主站与附属站播放列表物理隔离与零锁平滑割接
- **独立物理表隔离**：将附属站播放列表数据从主站 `movie_playlist` 彻底物理剥离至独立的 `slave_movie_playlists` 表，消除附属站高并发写入时对主站核心大表的行锁与间隙锁争用。
- **启动期自动化幂等割接**：启动时自动识别老表中存量附属站数据，采用 Redis 分布式排他锁 + 批次内存去重 + 500 条分块事务原子割接，老表数据分批安全删除，杜绝大事务阻塞与自增 ID 暴涨。

#### 2. 两阶段零锁并发孤儿治理状态机
- **48 小时留校察看期**：附属站先采集到、主站后收录时仅标记观察时间戳，留足 48 小时缓冲期，彻底规避并发时序错位导致的有效线路误杀。
- **临刑二次复核与原子 CAS 守卫**：物理删除前分批反查主站权威匹配键（`movie_match_key`），已收录资源原地复活；物理删除 SQL 带有 `orphan_marked_at` 严格状态与时间守卫，消除 TOCTOU 并发竞态。
- **主站切换 7 天冷启动保护期**：切换主站或清库时自动开启 7 天保护门禁，Redis 网络异常时遵循 Fail-Safe 保守安全原则，确保新主站爬取稳定前存量附属站资源零误删。

#### 3. 采集调度性能与写入短路优化
- **附属站落库无变更短路**：比对当前库内集数若无变动直接 short-circuit 快速返回，免开启事务与无谓的 DELETE/INSERT 操作。
- **同名多 MID 跨站匹配与追更比对**：修复跨站同名多 MID 共享 key 的追更检测场景，确保集数比对与追更通知百分之百准确。

#### 4. 毫秒级停机退出与启动自愈收尾
- **退出毫秒级清空版本**：彻底剔除从快照表盲目复活老快照的副作用，退出信号触发时 0.1ms 清除活跃快照版本号，手机/终端关闭服务秒级退出无卡顿。
- **启动期快照极简收尾**：启动时检测到版本为空，或因系统强杀导致数据库有效影片数与快照记录数不一致（`snapCount != dbCount`），瞬间在 100ms 内秒级激活最新全量快照，上次采集落库数据无缝完整展示。

#### 5. 全库健壮性加固与方言对齐
- **全库 Redis 防空指针 Panic**：在全库所有缓存读写入口（包括 TVBox 接口、鉴权模块、分类树等）全面补齐判空与优雅降级保护。
- **MySQL / SQLite 多环境方言对齐**：全量补齐各数据模型显式表名定义与 TRUNCATE/DELETE 统一包装，全库单元测试 100% 通过。
