正式版 **v2.7.4**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.7.4` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **平滑升级**：支持后台「检查更新」一键平滑升级，或通过 `docker compose pull ecohub && docker compose up -d ecohub` 快速拉取新镜像。
- **自动数据库对齐**：系统启动时自动执行迁移补齐 `update_reason` 字段，无需手动执行 SQL。
- **配置持久化**：系统配置、TMDB 刮削凭据与影片元数据持久化存储，升级无需重新初始化。

---

### v2.7.4 核心变更

- **智能轮播异步任务与实时进度轮询（根治 504 超时）**：
  - 排片生成全面改造为异步任务+进度轮询架构，毫秒级快速返回，彻底消除 Nginx 504 Gateway Timeout；
  - 优化刮削凑额发布流程，凑齐目标数量后一次性批量构建并发布快照与搜索索引，排片耗时与 DB 锁竞争降低 80% 以上；
  - 轮询进度文案简洁收敛，去除非实时片名闪烁跳动，提供平滑直观的排片体验。
- **排片分类精准多选与分类管理动态边界控制**：
  - 轮播配置新增“排片分类”多选，限定随机排片与 TMDB 刮削仅在指定分类范围内进行；
  - 联动「分类管理」显示开关：隐藏分类不可选；即使历史已选，在分类管理中关闭显示后依然实时严格过滤阻断；
  - 移除人工硬编码关键字黑名单，充分尊重用户选定的分类边界。
- **高并发写库死锁消除与标签热度保护**：
  - 修复标签聚合无序并发写入导致的 MySQL 1213 死锁，采用确定性排序从底层消除行锁逆序竞争；
  - 解耦单片增量更新与全量 Upsert，增量入库严格保护既有热门标签的累计热度分值，避免分类筛选热度排序失真。
- **智能轮播排片持续刮削与体验优化**：
  - 刮削目标调整为优先获取 TMDB 高清海报封面并兼顾横屏海报，横图缺失自动以高清海报优雅兜底；
  - 自动排片有效高清影片不足时，持续从候选池推进并发刮削直至凑满目标轮播数量（执行严格受超时预算控制）；
  - 彻底解绑年份强制校验限制，采集无年份数据支持严格同名命中，年份相符仅作为优选加分项；
  - 修复底层业务变更指纹遗漏横图字段导致写库和快照更新被跳过的缺陷，确保横图及高清海报实时同步。
- **播放页更新原因感知与极简展示**：
  - 播放页面更新时间后增加极简提示图标，鼠标悬浮即看更新原因（如“更新至第28集”、“新片入库”、“后台修改”）；
  - 存量与无变更影片无更新原因时不展示提示图标，保持页面极简克制；
  - 播放页顶部信息卡片抽离为模块化 `PlayHeaderCard` 组件，严格遵循 CSS Module 样式规范。
- **多源采集更新原因精准记录**：
  - 数据库 `film_index` 与快照 `film_list_snapshot` 表新增 `update_reason` 字段并接入启动迁移；
  - 附属源追更时自动提取最新分集数并动态写入（如“更新至第N集”），不再粗暴硬编码批量覆盖；
  - 主站入库与编辑精准记录“新片入库”与“后台修改”，连载剧集集数未变时不覆盖已有原因。
