正式版 **v2.7.2**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.7.2` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **平滑升级**：支持后台「检查更新」一键平滑升级，或通过 `docker compose pull ecohub && docker compose up -d ecohub` 快速拉取新镜像。
- **配置持久化**：系统配置、TMDB 刮削凭据与影片元数据持久化存储，平滑升级无需重新初始化。

---

### v2.7.2 核心变更

- **快照读模型性能大幅优化与索引体系治理**：
  - 快照表新增全局更新时间复合索引 `idx_snap_ver_update (snapshot_version, update_stamp, id)`，消除全表扫描与 filesort 文件排序开销，彻底解决管理后台默认列表高延迟问题（查询耗时由 8 秒级降至毫秒级）。
  - 清理无用且存在误导风险的复合索引 `idx_snap_ver_hits_pid`，并在分类热门查询中通过 FROM 子句后置 `USE INDEX` 精确绑定过滤性最佳索引，规避 MySQL 优化器错误扫描全快照，同时避免表名被驱动整段引用。
  - 前台分类多维标签筛选链路升级为两阶段延迟关联（Deferred Join），彻底消除万级记录多字段 filesort 磁盘临时表开销。
  - 阻断软删除索引合并与快照持久缓存：快照表去掉 `deleted_at` 索引并由启动流程幂等删除残留索引，所有快照读接口（前台首页/分类/搜索/相关推荐/热搜/每日更新/轮播、管理检索、TVBox Provide、访问日志回表、搜索内存索引构建）全面 `Unscoped()`，彻底阻断 GORM 自动注入 `deleted_at IS NULL` 触发 MySQL 灾难级单列索引交叉合并（Index Merge Intersect），并将标签搜索缓存 TTL 延长至 2 小时、对快照分类总数追加二级版本持久缓存，彻底消除冷请求扫描开销。
  - TVBox `/api/provide` 列表补齐剧情/地区/语言/年份筛选，与前台分类筛选共用 `applyTagSearchFilter`，避免筛选项只下发到客户端却不参与查询。
- **快照发布生命周期与首页缓存异步预热**：
  - 引入快照发布事件钩子机制，采集增量收尾发布新版本后，后台异步自动预热首页 Redis 缓存，彻底消除新版本发布时前台用户首次请求的冷启动并发击穿卡顿。
- **管理后台检索与前台搜索职责解耦**：
  - 重构管理后台检索链路，将纯片名打分搜索、多维结构化快照数据库筛选与底层降级清晰解耦，并优化空条件全量分页下的计数开销。
