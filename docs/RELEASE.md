- **从已有版本升级**：
  - **1Panel / Compose**：执行 `docker compose pull ecohub && docker compose up -d ecohub` 即可（或后台「检查更新」一键平滑升级）。
  - **数据结构与兼容性**：完全向下兼容现有 MySQL 与 Redis 数据结构，无破坏性变更。

### v2.6.1 核心变更

#### 1. 修复运行日志自轮询刷屏
- 管理后台「系统设置 → 运行日志」轮询 `GET /api/manage/system/logs/delta` 时，不再写入访问/运行日志，避免日志页读回自己产生的请求造成持续刷屏；
- 其余 `/api/manage/...` 访问日志仍正常打印。

### v2.6.0 历史核心变更

#### 1. 架构精简：单实例内存权威
- 影片列表活跃快照版本、主站切换保护期、孤儿播放列表游标改为进程内存读写，Redis 仅在启动时恢复、写入时备忘；
- Telegram Bot 由本进程直接长轮询；访问分析日滚动与清理仅用进程内互斥；
- 移除倒排表快照、残留废弃表、伪集群 3 秒轮询，以及多节点 / Nginx 负载均衡部署说明。

#### 2. 生产读路径与数据治理加固
- TVBox 核心快照查询引入 SingleFlight，并结合 Redis 缓存双检，避免并发击穿打满 MySQL 连接池；
- 孤儿播放列表清理游标与主站切换冷启动保护期可在重启后从 Redis 备忘恢复，清理批次间保留 15ms 微休眠削峰；
- 采集失败记录全链路恢复：落库、筛选、单页/全量重试，换源与删站时级联清理旧失败记录；
- 删除单片时在同一事务中级联清理 `slave_movie_playlists`，避免孤儿播放列表。

#### 3. 判更回归「集数严格增长」
- 有且仅当真实分集数严格增长时才刷新 `update_stamp`；备注文案变化、主站落后补录一律继承历史时间戳；
- 避免老片全量重爬或备注改写霸占最近更新，并向 Telegram / Webhook 重复推送虚假更新。

#### 4. 系统设置、权限与数据安全
- 通知配置、数据安全、运行日志收归「系统设置」二级 Tab，敏感操作仅超级管理员可执行，写操作二次校验管理密码；
- 访问分析支持按保留天数清理或全部清空；新增每日凌晨自动轮转清理 7 天前运行日志；
- 数据分析看板保留，入口与菜单严格跟随后端启用状态。

#### 5. 通知与前台体验
- Telegram Bot 支持按大类过滤与分页查阅；通知列表排序与前台每日更新对齐（最新在前）；
- 分类计划按更新时间重排时不再覆盖批次影片列表，摘要明细保持原始批次顺序；
- 修复搜索含空格或特殊字符时全屏 Loading 卡死约 15 秒的问题。

#### 6. 质量与回归验证
- **全仓测试**：Go 后端相关模块单元测试通过（含快照版本、主站切换保护、孤儿游标、访问分析清理、通知批次与权限控制）；
- **前端检查**：`npx tsc --noEmit` 0 错误。
