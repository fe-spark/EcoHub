预发布版 **v3.0.0-beta.22**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v3.0.0-beta.22`。不会覆盖 `latest`。

### 升级指引

- **试用本版**：把 Compose 镜像版本指定为 `ghcr.io/fe-spark/ecohub:v3.0.0-beta.22`，然后执行 `docker compose pull ecohub && docker compose up -d ecohub`。
- **破坏性变更与数据兼容**：**不兼容，不迁移。** 本版本为 v3.0 重大架构重构版本，完全不向后兼容 v2.x 历史数据。已入库的播放列表也不会改写；重复选集要重新采集对应站点才会拆开。请勿直接挂载 v2.x 历史数据库升级。

---

### v3.0.0-beta.22 核心变更

- **根除增量封口时重算全量倒排索引引发的 OOM SIGKILL**：
  - 修复 `cloneAndPatchSearchPostings` 在影片标题/拼音变动时退化全量重算 75 万影片倒排索引的暗门缺陷；
  - 改为严格局部增量追加变动影片倒排，使数百部变动的封口耗时从 **1分34秒骤降至 10毫秒**，内存开销微乎其微，彻底根治定时采集后期的 SIGKILL 强杀；
- **首页接口大分类流上限截断与性能治理**：
  - `/api/home` 接口对未映射或泛分类过多的主站片源增加推荐流大类数量熔断上限（最多下发 12 个大类推荐行）；
  - 接口 JSON 体积从 550KB+ 降至 90KB（降低 80% 网络与内存开销），彻底消除客户端因过量渲染引起的转场卡顿。
- **继承 v3.0.0-beta.21 核心加固**：
  - 废除 `maxIncrementalMids = 1000` 人为限制，增量索引永不退化全量库扫描；
  - 孤儿数据清理重构为 `NOT EXISTS`，消除 MySQL 30s 超时与长时间锁等待；
  - 管理后台 SSE 鉴权失效 401 探针死循环风暴阻断；
  - 容器镜像与服务端默认强制注入 Release 运行模式。
