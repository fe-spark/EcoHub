测试版 **v3.0.0-preview**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v3.0.0-preview`。

### 升级指引

- **从 v3.0.x 升级**：`docker compose pull ecohub && docker compose up -d ecohub`。
- **v2.x**：不兼容，不迁移。必须全新目录部署，勿挂载旧库。

### v3.0.0 核心演进与变更说明

#### 1. 核心架构演进：全站平权与物理隔离片库
- **告别主从绑定模式**：彻底废弃旧版 Master-Slave 主从依附架构，各采集站独立建档、物理隔离存储，单站数据异常不再影响全局片库。
- **毫秒级首选站切换**：后台采集站自由拖拽排序，首位站点即为前台基准源；切换即时生效，分类体系、分类规则与首选播放线路毫秒级对齐。
- **跨站片源智能聚合**：基于统一匹配键（豆瓣 ID、片名#分类、纯片名）动态聚合各站播放线路与高清海报，实现多源平权互备。
- **极简数据库基线**：彻底清理历史补丁与过时表结构，版本化迁移只保留空基线，后续变更按单向递增追加。

#### 2. 采集引擎重构：全速调度与高容错并发控制
- **全速直通调度**：移除采集站请求间隔等待（常态直通零延迟）与写库令牌桶限速，同站单页串行落库配合全局/单站有界缓冲反压，充分释放网络与数据库吞吐。
- **并发与超时隔离**：全局在途请求采用信号量槽位控制（128），单站固定分配 16 个工作协程；单页写事务注入 30 秒独立超时上下文，杜绝锁等待卡死。
- **零成功熔断与停止加速**：仅在没有任何成功页且取页失败达阈值时才熔断停站，避免网络轻微抖动误判中断；手动停止与配置导入瞬间丢弃未开写页面，平稳落盘正在写的事务，消除接口超时与卡死。
- **探页与抓页对齐**：JSON 探页使用 `detail`，XML 探页使用 `videolist`，与正式抓页同一协议，避免 list 与详情每页条数不同导致总页偏小。
- **智能补窗机制**：定时采集遇系统维护时自动让行，后续按实际未采窗口自动补齐（最高 7 天）。只有定时整次成功才把补窗锚点写成这次开始时间；手动采集和重试不移动锚点。

#### 3. 采集成果与批次记录体系
- **全新批次成果模型**：彻底废弃单一失败记录表，建立「批次记录（collect_records）」与「入库影片明细（collect_record_films）」两层完整追踪体系。
- **按真实产出判定成败**：批次与站点状态按实际落库产出标识为成功、部分成功、失败、已停止与异常中断。未抓页面写明「未抓」，不记成失败。更新部数按清单行数，同一影片在多站各算一行。
- **批次成果抽屉工作台**：支持按批次检索当次入库影片清单（新增/变动/更新），支持一键重试失败站点、按源筛选并直达播放。
- **自动生命周期归档**：成功批次自动归档，历史记录定时清理。

#### 4. 纯内存检索倒排索引与活跃读模型
- **自研内存检索架构**：摒弃外部重量级搜索引擎依赖，采用纯内存分词、拼音（全拼/简拼）倒排索引与分类榜单池。
- **毫秒级增量封口**：增量采集结束按需增量封口，同步重构最新/热播/年份榜单；存量影片更名自动重构倒排 posting，杜绝旧词脏召回。
- **纯增量定长封口与冷启重建分离**：采集收尾坚持纯增量追加并原地维护 Top 50 分类榜单，杜绝采集中途突发全库重扫；全库多协程范围分段重建仅在冷启动初始加载时执行，保障紧凑内存规格下的极速与稳定性。
- **读写分离与零锁读**：写路径流式推送与局部反压，读路径通过原子指针无锁访问，保障超高并发查询下的极低响应延迟。

#### 5. 前台与观影体验升级
- **首页精细化展示**：动态对齐首选站分类号与分类规则，自动隐藏空影片分类区块，杜绝「暂无相关数据」占位。
- **播放器与多源聚合**：支持多线路、多解析源平滑切换，支持集数智能排序与播放进度记忆。
- **原生弹幕生态**：原生接入弹幕播放与发送能力，支持弹幕后台独立配置与管理。
- **移动端对齐**：同步更新 Android 与 HarmonyOS 客户端协议保护与交互对齐。

#### 6. 后台工作台与数据安全体系
- **全局交互抽屉化**：全面重构原有弹窗为侧滑抽屉工作台，优化大屏与移动端操作流。
- **轮播图手动排片工作台**：首页轮播重构为卡片拖拽排片与 TMDB 独立刮削，支持自定义封面与一键排片。
- **数据安全一体化**：支持配置/站点/规则备份与导入，导入前秒级平滑停止采集；支持数据重置安全确认。
- **权限体系重构**：三级角色权限体系（超级管理员、管理员、普通用户），强化 API 鉴权守卫。

#### 7. 采集记录与运维体验强化
- **时效感知重试**：单站与批次重试支持 30 分钟时效判定，时效内精准重试失败页码，超时自动退化为整站兜底并输出明确引导日志。
- **业务视角文案统一**：全面剔除“入库”底层技术用词，无变动产出统一表达为客观的「无更新」，有变动统一呈现为「+N 部」。
- **批次详情像素级对齐**：统一错误提示行高基准线，实现红色警示图标与错误详情文字垂直居中对齐。
- **异常站点健康看板归位**：将异常站点从记录列表上方大面板彻底移除，迁移至采集中心站点卡片标题行，通过「已熔断 / 异常」标签与客观错误悬浮即时预警。
- **封口属于采集中**：待检索与抓页、停止收尾同属本次采集。此阶段不可删除站点，也不可修改地址或协议。
- **删站一次等待**：删除前只等一次检索索引、封口和主站预热结束。进行中的多站批次会摘掉已删站点，避免清库后被写回记录。
- **失败页只标红失败数**：采集中出现失败页时，站点卡片与圆环改为红色，状态仍是采集中。采集记录里成功进度保持原色，只有「失败 N」为红色。
- **待检索不按时间收口**：没有任务的采集中，以及没有占用的排队，当场标失败。待检索一直等到这次检索封口结束。
- **检索进度独立成条**：全部采集队列结束后另起一条检索进度，展示全库部数。采集队列只保留本队页进度。
- **有成功页仍进入待检索**：抓页有成功页时，失败页不挡住封口。零成功才直接失败。退出采集时不再把已经待检索的站点改回失败。
- **分类跳过单独计数**：分类未映射或已停用的影片记为跳过，这一页仍算成功。
- **队列总进度按站均分**：每个采集站各占一份。采集中按本站页进度填充，未探页为 0，无页的已结束站算完成。采集中最高 99%。页数只显示已采页。
- **采集站列表不再卡死**：查占用时先放开进度锁。列表接口记下进入、完成条数、耗时和失败原因。
- **小档不再限制写并发和站并发**：可用内存不超过 2GiB 时只收紧页并发、取数在途和写队列。写并发与站并发保持不限制。
- **增量封口跟随分类与来源**：影片分类或来源变化时，检索索引把条目从旧位置挪到新键。
- **相关推荐不再双缓存**：候选由检索层缓存，接口不再另写一份结果。
- **弹幕缓存按源区分**：更换弹幕源地址后不再命中旧缓存。
- **坏线路单独跳过**：单条播放线路解析失败只跳过该线路。整片线路都无法解析才报错。
- **配置缓存写失败删旧键**：配置已经落库后，缓存写失败会删掉旧值，避免继续命中旧配置。
- **影片库 ID 显示源站编号**：后台影片列表的 ID 列为当前来源的源站编号，不再显示本地入库序号。
