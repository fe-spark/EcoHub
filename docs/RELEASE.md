正式版 **v2.7.0**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.7.0` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **平滑升级**：支持后台「检查更新」一键平滑升级，或通过 `docker compose pull ecohub && docker compose up -d ecohub` 快速更新。
- **数据库索引自迁移**：启动时自动执行每日更新覆被复合索引迁移，无需手动干预。

---

### v2.7.0 核心变更

- **服务端架构深度重构**：
  - 全面拆解仓储层（`snapshot` / `writer` / `shared` / `poster` / `query`）与采集层（`fetcher` / `progress` / `scheduler` / `converter`）子包架构，严格践行单文件 ≤500 行规范。
  - 日志目录上溯至模块根目录，测试环境深度净化，消除单测对运行环境的副作用。
- **同名跨类智能打分与精准隔离**：
  - 建立同名跨类按豆瓣/名称/类别/标签/年份/备注形态综合打分机制，杜绝错源串源。
  - 错槽精准清理机制，仅清理同一部写到别人独占键上的历史旧行，保障数据一致性。
- **高可用性能与缓存闭环**：
  - 每日更新接口建立 `(update_stamp, mid)` 与 `(pid, update_stamp, mid)` 覆被复合索引，消除全量 Filesort 文件排序。
  - 每日更新统计与分页接入短缓存与 Singleflight 防击穿防穿透保护。
  - 读模型快照发布、主站切换、数据重置全链路闭环淘汰每日更新、影片详情、筛选列表及 TVBox 缓存。
  - 重置数据闭环：重置时连带清空强依赖影片的轮播图与采集失败记录，彻底杜绝首页死链与孤儿数据。
- **私有化访问安全控制体系**：
  - 支持私有化访问控制：开启时自动生成 16 位高强度安全随机密钥，支持后台一键重新随机生成与持久化兜底。
  - 重构拦截响应码与状态反馈（明确区分放行、403 密钥错误、401 需鉴权等），彻底解决客户端鉴权困惑。
- **接口与终端订阅规范化（`/api/provide/{终端}`）**：
  - 软件源配置页统一支持单地址栏直接填入（私有化源末尾追加 `?key=...`），移除冗余输入项与过时说明。
  - 工作台订阅地址弹窗精准对齐私有化开关：仅在开启私有化访问时自动拼接专属密钥参数，公开站点保持纯净端点路径。
- **网站系统配置模块化解耦**：
  - 网站配置重构为【网站基本信息】与【运行与访问控制】同页独立配置卡片，独立保存互不干扰。
  - 访问控制接口与基本配置接口针对访客角色实施密钥脱敏，杜绝安全越权隐患。
- **体验优化与缺陷修复**：
  - 修复无轮播 Banner 时顶部分类胶囊与 Header 重叠的排版问题，自适应顶部状态栏与安全区避让。
  - 修复标签筛选 others 条件被忽略返回全量数据的缺陷。
  - 管理端工作台新增采集队列进度展示。

正式版 **v2.6.8**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v2.6.8` 与 `ghcr.io/fe-spark/ecohub:latest`。

### 升级指引

- **平滑升级**：支持后台「检查更新」一键平滑升级，或通过 `docker compose pull ecohub && docker compose up -d ecohub` 快速更新。
- **历史数据归并（可选）**：历史附属站未对齐主键的旧播放列表可通过工具脚本一键归并：

```bash
docker exec -it ecohub /app/migrate_slave_playlist_keys --dry-run
docker exec -it ecohub /app/migrate_slave_playlist_keys
```

- **追集生效**：升级后对附属采集站再跑一轮采集即可自动对齐最新剧集。

---

### v2.6.8 核心变更

- **同名跨类隔离**：分类不编入 `mid`，通过匹配键大类隔离同名影片（如短剧与动漫），避免版本覆盖。
- **副站追集主键对齐**：附属站唯一命中一部影片时（含副站大类标错），播放列表自动对齐写入该片主键。
- **采集写入防锁优化**：附属站播放列表采用原地更新策略，避免多源并发写同一影片时产生死锁与堵塞。
- **多播放源站点隔离**：附属站剧集按 `source_id` 独立分列展示，不污染主站默认源。
- **详情展示最新剧集**：同站点存在多份列表时优先展示集数最多的一份，检测到变动即时刷新详情缓存。
- **采集卡慢与索引修复**：纠正 `movie_match_key` 索引定义并增加短路机制，消除几十万行全表扫描，采集恢复毫秒级。
- **版本化数据库迁移**：引入 `schema_migrations` 机制，表结构与历史补丁仅在升级时执行一次，避免启动重复开销。
- **采集站上限放宽**：取消 12 个采集站硬限制，改为高负载风险弹窗预警。
