### v2.5.7-beta.1 核心变更

#### 1. 附属站孤儿治理极简重构与 24 小时安全沉淀期
- **24 小时自然安全沉淀期**：将孤儿治理判定严格绑定为自然入库时间 `created_at < NOW() - 24h`，附属站新抓取入库未满 24 小时的记录天然受保护跳过，彻底为网络延迟和主站更新留足安全时间差，杜绝误删。
- **废除两阶段状态机与 19 万次打标写放大**：彻底推倒原有的 Mark 打标与 Purge 待决队列，不再对数据库执行数十万次无意义的 `UPDATE` 打标操作，消除磁盘 I/O 尖刺、Binlog/Redo Log 膨胀及行锁争用。
- **实时点查主站权威键，随时自愈**：清理微批执行时实时查验主站 `movie_match_key`，只要主站此时已收录该影片，立即判定为正常活跃数据安全放行，即使老数据历史曾被打标也绝不误删，随时自愈。

#### 2. 工业级高可用四大铁律保障生产平稳
- **Keyset Pagination（主键聚集索引步进）**：采用 `WHERE id > lastID ORDER BY id ASC LIMIT 1000` 扫描，消除大表深分页查询与慢 SQL。
- **安全配额限流（Quota 限额 5000 条 / 10 秒超时）**：单次定时任务执行物理删除最多 5000 条或满 10 秒即停，保存 Redis 断点游标退出，下次任务从断点平滑续扫；即使百万级历史数据同时跨过 24h 线，生产库负载依然平稳如水。
- **微批物理删除与批间微休眠**：每批 100 条物理硬删除，ID 升序排序消除行锁死锁，批间休眠 20ms 防 I/O 尖刺；带 `created_at < cutoff` 双重原子条件防御并发误删。
- **日志极简直观**：彻底告别晦涩的“新增待定标记”，任务日志直观明晰（`[CleanOrphan] 孤儿治理完成: 物理回收真孤儿=469, cost=10.012s`）。

#### 3. 全工程冗余代码彻底拔除
- **移除废弃字段与二级索引**：从 `SlaveMoviePlaylist` 模型中彻底移除 `OrphanMarkedAt` 字段及 `idx_slave_orphan_marked` 索引，模型纯净回归基础业务属性。
- **消除主站高频写入路径的无意义探针**：移除主站每次入库生成匹配键时调用的 `ReviveSlavePlaylistsTx` 数据库查询探针与 UPDATE 操作，主站爬虫抓取写入更轻更快。
- **清理日常 Upsert 与主站切换冗余逻辑**：移除从站日常写入中的标记列更新与主站切换时的全表清标 UPDATE。
