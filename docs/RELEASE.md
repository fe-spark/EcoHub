测试版 **v3.0.0-preview**，Docker 镜像 `ghcr.io/fe-spark/ecohub:v3.0.0-preview`。

### 升级指引

- **从 v3.0.x 升级**：`docker compose pull ecohub && docker compose up -d ecohub`。
- **v2.x**：不兼容，不迁移。必须全新目录部署，勿挂载旧库。

### v3.0.0 核心演进与变更说明

#### 1. 核心架构演进：全站平权与物理隔离片库
- **告别主从绑定模式**：彻底废弃旧版 Master-Slave 主从依附架构，各采集站独立建档、物理隔离存储，单站数据异常不再影响全局片库。
- **毫秒级首选站切换**：后台采集站自由拖拽排序，首位站点即为前台基准源；切换即时生效，分类体系、分类规则与首选播放线路毫秒级对齐。
- **跨站片源智能聚合**：基于统一匹配键（豆瓣 ID、片名#分类、纯片名）动态聚合各站播放线路与高清海报，实现多源平权互备。
- **极简数据库基线**：彻底清理历史补丁与过时表结构，版本化迁移只保留空基线，后续变更按单向递增追加。

#### 2. 采集引擎重构：全速调度与高容错并发控制
- **全速直通调度**：移除采集站请求间隔等待（常态直通零延迟）与写库令牌桶限速，同站单页串行落库配合全局/单站有界缓冲反压，充分释放网络与数据库吞吐。
- **并发与超时隔离**：全局在途请求采用信号量槽位控制（128），单站固定分配 16 个工作协程；单页写事务注入 30 秒独立超时上下文，杜绝锁等待卡死。
- **零成功熔断与停止加速**：仅在没有任何成功页且取页失败达阈值时才熔断停站，避免网络轻微抖动误判中断；手动停止与配置导入瞬间丢弃未开写页面，平稳落盘正在写的事务，消除接口超时与卡死。
- **探页请求轻量化**：JSON 与 XML 采集站总页数探测默认采用轻量 `ac=list`，单次探页传输从数百 KB 缩减至几 KB，节约 95% 以上探页带宽。
- **智能补窗机制**：定时采集遇系统维护时自动让行，后续按实际未采窗口自动补齐（最高 7 天）；手动采集成功同步刷新采集锚点，避免无谓的重复超大窗口采集。

#### 3. 采集成果与批次记录体系
- **全新批次成果模型**：彻底废弃单一失败记录表，建立「批次记录（collect_records）」与「入库影片明细（collect_record_films）」两层完整追踪体系。
- **按真实产出判定成败**：批次与站点状态按实际落库产出精确标识为成功（success）、部分成功（partial）、失败（failed）与已停止（stopped）；未抓取页面明确标识为「未抓」，不再将未抓页面误算为失败。
- **批次成果抽屉工作台**：支持按批次检索当次入库影片清单（新增/变动/更新），支持一键重试失败站点、按源筛选并直达播放。
- **自动生命周期归档**：成功批次自动归档，历史记录定时清理。

#### 4. 纯内存检索倒排索引与活跃读模型
- **自研内存检索架构**：摒弃外部重量级搜索引擎依赖，采用纯内存分词、拼音（全拼/简拼）倒排索引与分类榜单池。
- **毫秒级增量封口**：增量采集结束按需增量封口，同步重构最新/热播/年份榜单；存量影片更名自动重构倒排 posting，杜绝旧词脏召回。
- **大变动量自适应重建**：变动超过两万条或全库同步时，自适应切换为多协程范围分段游标扫描全库重建，1~2 秒完成全库索引加载。
- **读写分离与零锁读**：写路径流式推送与局部反压，读路径通过原子指针无锁访问，保障超高并发查询下的极低响应延迟。

#### 5. 前台与观影体验升级
- **首页精细化展示**：动态对齐首选站分类号与分类规则，自动隐藏空影片分类区块，杜绝「暂无相关数据」占位。
- **播放器与多源聚合**：支持多线路、多解析源平滑切换，支持集数智能排序与播放进度记忆。
- **原生弹幕生态**：原生接入弹幕播放与发送能力，支持弹幕后台独立配置与管理。
- **移动端对齐**：同步更新 Android 与 HarmonyOS 客户端协议保护与交互对齐。

#### 6. 后台工作台与数据安全体系
- **全局交互抽屉化**：全面重构原有弹窗为侧滑抽屉工作台，优化大屏与移动端操作流。
- **轮播图手动排片工作台**：首页轮播重构为卡片拖拽排片与 TMDB 独立刮削，支持自定义封面与一键排片。
- **数据安全一体化**：支持配置/站点/规则备份与导入，导入前秒级平滑停止采集；支持数据重置安全确认。
- **权限体系重构**：三级角色权限体系（超级管理员、管理员、普通用户），强化 API 鉴权守卫。
