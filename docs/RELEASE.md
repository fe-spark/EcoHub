### 升级说明

- v3.0.x：通过 `ecohub` 安装的，执行 `ecohub update`；使用 1Panel 或自行维护 compose 的，在安装目录执行 `docker compose pull && docker compose up -d`。
- **v3.0.3 不再读取 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`**：编排文件和 `.env.example` 已移除这三个变量，旧 `.env` 中保留的值不再生效。此前依赖这些变量使弹幕或 Telegram 通过代理访问的，升级后须在后台「网络代理」开启全局代理，并开启「弹幕抓取」或「Telegram 机器人」模块，否则相关请求将直连。
- v2.x：不兼容，不提供迁移。见 [从 v2 升级到 v3](https://github.com/fe-spark/EcoHub/blob/main/docs/v2-to-v3.md)。

### v3.0.5 更新内容

- **播放页**：未指定片源时播放主站。可开启测速优选，对当前集各线路按持续速度自动选择；侧栏显示测速结果，支持重新测速，手动选择不会被自动结果覆盖。测速默认关闭。播放失败时只提示错误，不再自动切换线路（#87，#91）。
- **采集加入未封口的一轮**：封口周期已经打开、仍有采集队列在跑时，新的定时或手动采集加入这一轮，全部队列结束后再封口。当前没有队列时拒绝新开。同一批次里尚未开跑的站，不会因为前面的站已经进入待检索而被标成失败。自动采集重叠到点时，当前队列结束后再补采一轮当时空闲的站。不能新开时写明是检索索引正在更新，或这一轮检索即将入库，正在进行的采集会继续跑完。入队被拒绝时立刻放开已经占住的站（#92）。
- **检索索引封口**：全部采集队列结束后只封一次。含全量站、内存索引不可用、条目数为 0，或变动编号已经超过当前索引一半时，在按编号点查之前整表顺序加载。小时窗口里不超过一半的完整增量才按编号打补丁，点查失败同样改为整表加载。只有本轮重建成功才结束采集（#92）。
- **临时断连**：已有成功页的站点连续遇到 EOF、连接重置或单页超时，先暂停约 15 秒再补抓这些页，不立刻记成部分失败。每页最多补两轮，整站最多短暂停 3 次；仍失败时再按连续失败页和 5 分钟长暂停处理（#92）。
- **工作台失败页**：工作台「采集失败页数」为北京时间当天的失败页合计，各站可以展开。批次明细里的错误可打开弹窗，分开显示原因、请求地址和失败页。新采集的错误原因保留到 2000 字（#95）。

### 架构

- 取消主从绑定。各采集站独立建档，单个采集站异常不影响其他采集站。
- 已启用采集站中排序第一的为前台主站。切换主站后立即展示该站已有数据，不重新采集、不删除影片；轮播按采集站分别保存，首页展示新主站的轮播。
- 播放页按匹配键附加其他采集站的线路，匹配键依次为：豆瓣 ID + 片名、片名#分类、片名。线路按采集站分组，不合并档案。
- 结构迁移仅保留空基线，新变更只在末尾追加。

### 采集

- 移除请求间隔和写库令牌桶。全局在途请求上限 128，单站 16 个协程，单页写事务超时 30 秒。
- 仅当零成功且取页失败达到阈值时熔断。已有成功页的采集站连续遇到连接中断或单页超时时，先暂停约 15 秒并补抓这些页；仍失败则连续失败 20 页时暂停 5 分钟后续采，连续暂停 3 次仍失败则结束本轮。停止或导入时丢弃尚未开始写入的页，已打开的事务写完后结束。
- JSON 探页使用 `detail`，XML 探页使用 `videolist`，与正式抓页一致。
- 定时采集遇到维护任务时让行，之后按未采集的时间窗口补采，最多 7 天。封口周期已打开且仍有队列在跑时，新的定时或手动采集加入这一轮；当前没有队列时不再新开。仅当定时采集整体成功时才移动补采锚点。规则见 [计划任务冲突](https://github.com/fe-spark/EcoHub/blob/main/docs/cron-task-conflict.md)。
- 采集批次记录在 `collect_records`，入库明细记录在 `collect_record_films`。状态按实际入库结果记录：成功、部分成功、失败、已停止、异常中断。未抓取的页标记为未抓取。
- 30 分钟内重试失败页，超时则整站重新采集。成功批次归档，历史记录定时清理。
- 未映射的影片归入该站一级分类「其他」（源站的「其它」视为同一分类）。隐藏或停用的分类（含「其他」）仍正常采集入库，但不在前台展示。存在成功页时仍进入待检索；零成功时直接判定为失败。
- 封口期间不能删除采集站，也不能修改地址或协议。删除采集站只需等待一次检索收尾。
- 可用内存不超过 2GiB 时，仅收紧页并发、取数在途数量和写队列。

### 检索与前台

- 内存倒排索引（分词、全拼、简拼）和分类榜单，随采集增量更新。启动时全量重建一次。封口在全部采集队列结束后进行，只走一次。含全量站、没有可用索引、条目数为 0、变动编号超过当前索引一半，或读库失败时，在按编号点查之前整表顺序加载。小时窗口里不超过一半的完整增量按变动编号打补丁。
- 首页隐藏没有影片的分类，分类区块最多显示 12 个一级分类。导航、筛选和 TVBox 仍使用该站的全部分类。
- 分类规则按采集站生效。前台分类的排序和显示跟随管理端映射。隐藏分类（含规则合并组）从前台所有接口中移除，旧地址显示分类已失效；搜索、每日更新和 TVBox 关键词也不返回这些影片。采集仍将这些影片入库，分类管理中仍可查看并重新开启。子分类不会自动提升为一级分类。
- 未映射的影片显示在该站的「其他」分类中。源站改名占用原「其他」编号时，自动分配新编号。
- 播放器支持多线路、进度记忆和弹幕。未指定片源时播放主站。测速优选默认关闭；开启后按当前集各线路的持续速度自动选择，播放失败时不再自动切换线路。更换弹幕源后不再命中旧缓存。
- **图片加速**：开启媒体反代后，前台与 TVBox 海报自动通过边缘 CDN 加载，无需代理即可直接访问，不占用自建服务器带宽。

### 后台

- 操作改为抽屉形式。配置、采集站和规则支持备份与导入，导入前会停止采集。
- **轮播**：按采集站存储，片名、分类、备注等信息从片库实时组装；该站已无播放线路的影片不在首页展示，后台标记为已失效，可删除和排序。手动增删改及排序操作带版本号校验，并发修改时提示刷新。
- **一键排片**：选择策略（最新、最热、高分）和各分类数量，每个分类最多 5 部，总数不限；结果在抽屉中预览、调整后整组发布。排片配置不入库，每次一键排片均弹窗确认，默认为最热、每类 1 部；同一页面内再次排片沿用该站上次的选择，刷新页面后恢复默认。
- 分类管理与前台共用同一套规则树，仅调整排序和显示。父级分类隐藏时，子分类开关不可修改。
- 角色分为超级用户、普通用户和访客。
- 影片列表的 ID 列为源站编号。采集过程中的失败页仅将失败数标红。
- 单条无效线路只跳过该线路。配置已入库后，如缓存写入失败则删除旧缓存值。
- **媒体反代**：支持边缘反代模板的配置与校验，服务端在出站时动态替换海报地址，不修改原始数据。
