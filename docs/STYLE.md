# 文档写作规范

本文只有中文版。

这份规范管仓库里所有 Markdown 文档。新写或改动文档前先看一遍。

## 文档类型和结构

每篇文档只属于一种类型，按下表的顺序排二级标题。用不上的节可以省略，顺序不要换。

| 类型 | 文件 | 二级标题顺序 |
| --- | --- | --- |
| 总览 | `README.md`、`docs/README_EN.md` | 简介 → 在线演示 → 推荐 → 安装 → 本地开发 → 文档 |
| 文档索引 | `docs/README.md` | 只有一张表 |
| 部署 | `docs/README-Deploy*.md` | 准备 → 安装方式（每种一节）→ 自备数据库 → 访问地址 → 反向代理 → 环境变量 → 排障 → 相关 |
| 升级 | `docs/v2-to-v3.md` | 结论 → 不要做的事 → 步骤（每种一节）→ 怎样算完成 → 相关 |
| 常见问题 | `docs/README-FAQ*.md` | 按主题分二级标题，每个问题一个三级标题 |
| 设计说明 | `docs/cron-task-conflict.md` | 一句话规则 → 涉及的对象 → 规则 → 例子 → 实现 → 相关 |
| 版本说明 | `docs/RELEASE.md` | 见下文「版本说明」 |
| 开发说明 | `server/README.md`、`web/README.md` | （可选）整体流程 → 本地启动 → 环境变量 → 关键行为（每项一节）→ 目录 → 命令 → 相关 |

## 标题

- 一篇文档只有一个一级标题。总览的一级标题在居中的 HTML 块里，其余文档写在第一行。
- 一级标题下面紧跟语言切换行：`中文 | [English](./xxx_EN.md)`，英文版反过来。没有另一种语言时写「本文只有中文版。」
- 正文只用二级和三级标题，不用四级。
- 三级标题用来拆分一节里的小主题。常见问题里每个问题是一个三级标题，以问号结尾。

## 写法

- 先给结论，再给原因或例子。一段只讲一件事。
- 说人话。能用一个例子讲清楚的，就给例子，例如「02:00 片库清理和整点采集同时到点，采集跳过」。
- 不写宣传语，例如「强大」「极速」「完美」。
- 只写能在代码、脚本、编排里查到的事实。查不到的不写，或者交给维护者确认后再写。
- 默认值、端口、时间、路径、变量名都用代码格式，例如 `3000`、`~/ecohub`、`JWT_SECRET`。
- 中文和英文、数字之间留一个空格，标点用中文全角。
- 界面上的按钮、菜单名用「」括起来，并和界面文字一字不差，例如「采集中心」「计划任务」。

## 术语表

一个概念只用一个叫法。中英文对照如下。

| 中文 | English | 含义 |
| --- | --- | --- |
| 采集站 | collect source | 后台「采集中心」里配置的一个上游采集接口 |
| 主站 | main source | 已启用采集站里排序最前的一座，决定前台展示哪一站的数据 |
| 海报源 | poster source | 提供前台封面的采集站，和主站是两回事 |
| 片库 | library | 所有采集站入库的影片，核心表是 `film_index` |
| 线路 | play line | 一个采集站给一部影片的一组播放地址 |
| 匹配键 | match key | 跨站认出「同一部片」用的键 |
| 快照 | snapshot | 前台、后台列表和订阅接口读取的只读数据，采集时按批刷新 |
| 全量采集 / 增量采集 | full collect / incremental collect | 拉取采集站全部页 / 只拉最近若干小时更新的页 |
| 计划任务 | scheduled task | 后台「计划任务」页里的定时任务，分采集任务和维护任务 |
| 维护任务 | maintenance task | 片库清理、日志清理、采集记录清理 |
| 前台 / 后台 | site / admin | 观影页面 / 管理后台 `/manage` |
| 订阅地址 | subscription URL | `/api/provide/app`、`/api/provide/tvbox`、`/api/provide/vod` |
| 发布镜像 | release image | `ghcr.io/fe-spark/ecohub`，Go API 和 Next.js 在同一个容器里 |
| 安装目录 | install directory | `ecohub` 命令管理的目录，默认 `~/ecohub` |
| Web 端口 / API 直连端口 | web port / direct API port | 默认 `3000` / `18080` |

## 代码块和命令

- 代码块都标语言：`bash`、`env`、`text`、`yaml`。
- 命令前不加 `$`，一行一条，能直接复制运行。
- 需要用户替换的值用中文说明，例如 `请改成强密码`、`<服务器IP>`。
- 长命令用 `\` 换行。

## 表格

- 查表用的内容用表格：环境变量、地址、任务、文档列表。
- 步骤和原因用段落或编号列表，不塞进表格。
- 环境变量表固定四列：部署文档用「变量、默认值、谁读、说明」，开发说明用「变量、默认值、必填、说明」。

## 链接

- 仓库内文件用相对路径，例如 `[部署指南](./README-Deploy.md)`。
- `docs/RELEASE.md` 会原样贴到 GitHub Release 页面，相对路径在那里打不开，所以它里面的链接一律写完整地址 `https://github.com/fe-spark/EcoHub/blob/main/...`。
- 链接文字写目标文档的标题，不写「点这里」。
- 每篇文档末尾的「相关」一行列出同类文档。

## 中英文对照

- 有英文版的文档（总览、部署、常见问题）结构和中文版一一对应：同样的标题顺序、同样的表格、同样的代码块。
- 改中文版时同一个提交里改英文版。
- 英文版链接到只有中文版的文档时，在链接后写 `(Chinese)`。

## 版本说明

`docs/RELEASE.md` 是 GitHub Release 正文，推到 `main` 会触发 `.github/workflows/github-release.yml` 重新发布当前版本。

- 第一行写版本号和镜像 tag，不加一级标题。
- 用三级标题分组，顺序固定：升级、`vX.Y.Z 修复`、架构、采集、检索与前台、后台。
- 每条以加粗短语开头时，短语后面用全角冒号。
- 关联的 issue 或 PR 写在句末括号里，例如（#80）。
