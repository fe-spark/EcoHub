# 文档写作规范

本文只有中文版。

本规范适用于仓库内所有 Markdown 文档。新增或修改文档前请先阅读本规范。

## 文风

文档采用正式、简洁的技术文档文风，参照主流开源项目的写法。

- 使用中性、客观的陈述句；操作说明使用祈使句，例如「执行以下命令」「将 `JWT_SECRET` 设为随机字符串」。
- 不使用第二人称「你」「您」。需要指代读者时，使用「用户」「管理员」「部署者」，或直接省略主语。
- 不使用口语、语气词和填充语，例如「说人话」「其实」「一下」「就行」「搞定」「举个例子」「注意了」。
- 不使用反问句、感叹句、表情符号和网络用语。常见问题的标题可以使用疑问句。
- 不写宣传语，例如「强大」「极速」「完美」「一键搞定」。
- 先写结论或要求，再写原因。一段只说明一件事，句子保持简短。
- 示例只在规则不易理解时使用，并以「示例：」开头，单独成段或成列表项。
- 只写能在代码、脚本、编排中核实的事实。无法核实的内容不写，或交由维护者确认后补充。

英文版使用标准技术英文：

- 操作说明使用祈使句（Run, Set, Open），描述性内容使用一般现在时和第三人称。
- 不使用 you / your（引用界面文字时除外），不使用缩写形式（don't、it's）。
- 不使用口语表达，例如 just、simply、basically、pretty、a lot。

## 文档类型和结构

每篇文档只属于一种类型，二级标题按下表顺序排列。不适用的章节可以省略，但不得调整顺序。

| 类型 | 文件 | 二级标题顺序 |
| --- | --- | --- |
| 总览 | `README.md`、`docs/README_EN.md` | 简介 → 主要功能 →（截图）→ 技术架构 → 快速开始 → 文档 → 目录结构 → 参与贡献 → 许可证 |
| 文档索引 | `docs/README.md` | 仅包含一张表 |
| 部署 | `docs/README-Deploy*.md` | 准备 → 安装方式（每种一节）→ 自备数据库 → 访问地址 → 反向代理 → 环境变量 → 故障排查 → 相关文档 |
| 升级 | `docs/v2-to-v3*.md` | 概述 → 注意事项 → 操作步骤（每种一节）→ 验证 → 相关文档 |
| 常见问题 | `docs/README-FAQ*.md` | 按主题划分二级标题，每个问题一个三级标题 |
| 设计说明 | `docs/cron-task-conflict*.md` | 规则摘要 → 相关对象 → 规则 → 示例 → 实现 → 相关文档 |
| 版本说明 | `docs/RELEASE*.md` | 见下文「版本说明」 |
| 开发指南 | `docs/README-Dev*.md` | 环境要求 → 开发编排 → 启动方式（每种一节）→ 注意事项 → 相关文档 |
| 开发说明 | `server/README*.md`、`web/README*.md` | （可选）整体流程 → 本地启动 → 环境变量 → 关键行为（每项一节）→ 目录结构 → 常用命令 → 相关文档 |

## 标题

- 每篇文档只有一个一级标题。总览的一级标题位于居中的 HTML 块内，其余文档的一级标题位于第一行。
- 一级标题下方紧跟语言切换行：`中文 | [English](./xxx_EN.md)`，英文版相反。没有对应语言版本时写「本文只有中文版。」
- 正文只使用二级和三级标题，不使用四级标题。
- 标题使用名词短语，例如「环境变量」「反向代理」。常见问题的三级标题使用疑问句，以问号结尾。
- 已被其他文档或外部链接引用的标题不随意改名。必须改名时，同时更新所有引用该锚点的链接。

## 格式

- 默认值、端口、时间、路径、变量名、命令使用代码格式，例如 `3000`、`~/ecohub`、`JWT_SECRET`。
- 中文与英文、数字之间留一个空格，中文语境使用全角标点。
- 界面上的按钮和菜单名使用「」括起，并与界面文字完全一致，例如「采集中心」「计划任务」。
- 需要提醒的内容使用 GitHub 提示块（`> [!NOTE]`、`> [!WARNING]`），不使用「注意：」开头的段落。

## 术语表

同一概念只使用一个名称。中英文对照如下。

| 中文 | English | 含义 |
| --- | --- | --- |
| 采集站 | collect source | 后台「采集中心」中配置的一个上游采集接口 |
| 主站 | main source | 已启用采集站中排序最前的一个，决定前台展示哪一站的数据 |
| 海报源 | poster source | 提供前台封面的采集站，与主站相互独立 |
| 片库 | library | 所有采集站入库的影片，核心表为 `film_index` |
| 线路 | play line | 一个采集站为一部影片提供的一组播放地址 |
| 匹配键 | match key | 跨站识别同一部影片所用的键 |
| 快照 | snapshot | 前台、后台列表和订阅接口读取的只读数据，采集时按批刷新 |
| 全量采集 / 增量采集 | full collect / incremental collect | 拉取采集站全部页 / 只拉取最近若干小时内更新的页 |
| 计划任务 | scheduled task | 后台「计划任务」页面中的定时任务，分为采集任务和维护任务 |
| 维护任务 | maintenance task | 片库清理、日志清理、采集记录清理 |
| 前台 / 后台 | site / admin | 观影页面 / 管理后台 `/manage` |
| 订阅地址 | subscription URL | `/api/provide/app`、`/api/provide/tvbox`、`/api/provide/vod` |
| 发布镜像 | release image | `ghcr.io/fe-spark/ecohub`，Go API 与 Next.js 运行在同一个容器内 |
| 安装目录 | install directory | `ecohub` 命令管理的目录，默认 `~/ecohub` |
| Web 端口 / API 直连端口 | web port / direct API port | 默认 `3000` / `18080` |

## 代码块和命令

- 代码块均标注语言：`bash`、`env`、`text`、`yaml`。
- 命令前不加 `$`，每行一条，可直接复制执行。
- 需要替换的值使用说明性占位符，例如 `请改成强密码`、`<服务器IP>`。
- 长命令使用 `\` 换行。

## 表格和列表

- 供查阅的内容使用表格：环境变量、地址、任务、文档列表。
- 有先后顺序的操作使用编号列表；原因和说明使用段落，不放入表格。
- 环境变量表固定四列：部署文档为「变量、默认值、读取方、说明」，开发说明为「变量、默认值、必填、说明」。

## 链接

- 仓库内文件使用相对路径，例如 `[部署指南](./README-Deploy.md)`。
- `docs/RELEASE.md` 的内容会原样发布到 GitHub Release 页面，相对路径在该页面无法打开，因此其中的链接一律使用完整地址 `https://github.com/fe-spark/EcoHub/blob/main/...`。
- 链接文字使用目标文档的标题，不使用「点这里」一类文字。
- 每篇文档末尾的「相关文档」列出同类文档。

## 中英文版本

- 除本规范外，每篇文档都有英文版（`xxx_EN.md`，与中文版位于同一目录）。英文版与中文版结构一一对应：标题顺序、表格和代码块保持一致。
- 修改中文版时，在同一个提交中同步修改英文版。
- 英文版中的链接指向英文版文档；只有中文版的文档（目前仅本规范），在链接后注明 `(Chinese)`。

## 版本说明

`docs/RELEASE.md` 是 GitHub Release 的正文。推送到 `main` 时会触发 `.github/workflows/github-release.yml`，以该文件全文发布或更新当前版本的 Release。

- 第一行写明版本号和镜像 tag，不加一级标题。第二段为语言切换行，链接使用完整地址。
- 英文版 `docs/RELEASE_EN.md` 与中文版结构一致，但不会触发发布，也不会出现在 Release 页面。
- 使用三级标题分组，顺序固定：升级说明、`vX.Y.Z 更新内容`、架构、采集、检索与前台、后台。
- 条目以加粗短语开头时，短语后使用全角冒号。
- 关联的 issue 或 PR 写在句末括号内，例如（#80）。
