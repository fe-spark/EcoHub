## 采集与数据

### 部署完成后前台为什么没有影片？

尚未执行采集。发布镜像不包含影视数据，首次启动只写入 12 个预设采集站，不会自动执行全量采集。

请在后台「采集中心」执行一次全量采集。采集站越多耗时越长，首次采集可能需要数小时。无需等待全部完成：每采集完一批，该批数据即刷新到前台读取的快照中，主站的影片会随采集进度陆续出现。

前台列表、后台影片列表和 TVBox / MacCMS 订阅均读取快照，不直接读取采集中的表。因此在第一批数据刷新前，前台为空属于正常现象。

### 什么是主站？

主站是已启用采集站中排序最前的一个。前台首页、分类、搜索和每日更新只展示主站采集到的影片和分类。

示例：采集站顺序为 A、B、C 且均已启用时，主站为 A。将 B 移到最前后，前台立即切换为 B 已采集的数据，不会重新采集，也不会删除 A 和 C 的数据。所有采集站均停用时不存在主站。

播放页以主站的影片为基准，通过匹配键查找其他已启用采集站中的同一部影片，并将其线路附加在后。线路按采集站分组显示。

海报源是独立的标记，不决定主站。前台封面优先使用海报源中匹配到的同一部影片的封面，无法匹配时使用主站自身的封面；海报源与主站相同时直接使用主站的封面。

### 切换主站会清除哪些数据？

不会清除任何数据。切换主站不删除影片、不重新采集，采集进行中也可以切换。

首页轮播按采集站分别保存。切换后首页展示新主站的轮播，原主站的轮播仍然保留，切换回原主站后即可恢复显示。

以下两项操作与切换主站不同：

- 修改某个采集站的采集地址：清空该站的影片、线路、失败记录和分类（包括没有播放线路的影片），然后重新拉取分类。其他采集站不受影响。
- 删除某个采集站：同样只清除该站的数据。

### 影片如何去重和跨站匹配？

每个采集站的数据独立保存，采集时不合并。

- 同一采集站内：`movie_source_mapping` 通过「采集站 + 采集站提供的 `vod_id`」识别影片的已有记录，再次采集时只更新该条记录。同一采集站同一页中匹配键相同的条目合并为一部影片。
- 不同采集站之间：匹配键不用于合并记录，仅在播放页读取时用于查找其他采集站的同一部影片。查找顺序为：豆瓣 ID + 片名，片名 + 大类，片名。多个键命中同一部影片时只计一次。线路按采集站分组，不会合并不同采集站的剧集。

分类的键为 `source:{采集站 ID}:{采集站分类 ID}`，与该采集站自身的分类树一一对应。

### 刮削结果和首页轮播保存在哪里？

- 影片刮削：直接修改该影片所选的封面、简介、评分等字段，片名和分类不变。修改后不支持还原。
- 首页轮播：按采集站分别保存。每条记录只保存影片、排序，以及在后台修改过的图片、简介、评分、年份；其余信息在展示时从片库实时读取。在轮播中刮削只修改该条轮播记录，不修改影片本身，也不存在单独的刮削表。

### 手动停止采集后数据处于什么状态？

停止操作会中断正在拉取的页。已成功入库的页保留在片库中；正在写库的页会完成写入，排队等待写库的页直接丢弃。失败的页记录在「采集记录」中，可以重试。

## 快照与缓存

### 采集过程中为什么需要刷新快照？

前台不直接读取采集中的表。采集过程中数据表持续变化，因此每采集完一批，即将该批数据刷新到快照中，并按影片增量更新内存中的搜索索引。前台列表、筛选、后台影片列表和 TVBox / MacCMS 均读取快照。

刷新完成后，列表缓存的清理有 5 秒防抖：连续处理多批数据时不会每批都清理 Redis，而是在最后一批完成约 5 秒后统一清理。

搜索索引平时只进行增量更新。启动时全量加载一次；增量更新时如发现内存中没有可用的索引，也会补做一次全量重建。

### 修改配置后前台为什么没有立即生效？

网站配置保存后会更新 Redis 并清除首页缓存。页面仍显示旧内容时，常见原因如下：

- 浏览器、CDN 或反向代理存在缓存。
- 运行的不是最新的代码或镜像。

影片列表、分类和筛选只读取当前主站的数据。切换主站后立即展示新主站已采集的影片；新主站尚未采集时，列表为空。

TVBox 的常规列表另有一层 Redis 缓存，最长约 12 小时，入库后按防抖规则清理。如仍不一致，请先确认访问的是同一实例且请求参数相同。

### 「最近更新」如何排序？分类页与 TVBox 是否一致？

按 `film_index.update_stamp` 从新到旧排序，相同时再按 `mid` 排序。

- 新入库的影片：使用采集站提供的更新时间。
- 已入库的影片：采集时仅当播放线路发生变化，才将时间更新为本次采集的时间。只修改下载线路、备注、演员或封面时，排序不变。
- 在后台手动保存影片时，也会将其时间更新为保存时间。

所有采集站适用同一规则。

前台分类页与 TVBox 的筛选项来自同一份筛选项数据，匹配规则相同，区别在于前台查询内存索引，TVBox 查询 MySQL：

| 筛选 | 规则 | 是否一致 |
| --- | --- | --- |
| 分类 | 按该采集站的分类规则展开为同一组源站分类（含合并组），只列出包含该站播放线路的影片 | 一致。前台使用主站，TVBox 使用订阅中各站点各自的采集站 |
| 剧情 | 影片的剧情标签包含所选值 | 一致 |
| 地区、语言 | 与所选值完全相同 | 一致 |
| 年份 | 等于所选年份；传入值不是数字时不筛选 | 一致 |
| 「其他」 | 取值不在筛选项中，包括空值 | 一致 |
| 排序 | 最近更新、人气、评分、时间。按「时间」排序时，同一年份再按更新时间排序 | 一致 |

两者均有 Redis 缓存，但缓存时长不同：前台筛选结果为 2 小时；TVBox 不带剧情、地区、语言、年份条件的列表页约 12 小时，带条件的为 3 分钟。出现短时不一致时，请先排查缓存。

## 网络

### 哪些请求走后台「网络代理」？

仅当后台「网络代理」（`/manage/system/proxy`）开启全局代理，且对应模块的开关也已开启时，该模块的请求才通过代理发出；其他情况一律直连。容器的环境变量不影响出站方式。

| 模块（后台名称） | 涵盖的请求 | 全新安装默认值 |
| --- | --- | --- |
| 影视采集爬虫 | 采集站接口。每个采集站还需在编辑页单独开启「采集接口代理」 | 开启 |
| TMDB 刮削 | 对 TMDB 接口的请求（含后台的连通测试） | 开启 |
| Telegram 机器人 | 通知推送和翻页按钮的轮询 | 开启 |
| 系统版本更新 | GitHub 版本检查 | 开启 |
| 弹幕抓取 | 弹弹play 官方接口或自建 danmu-api 的弹幕搜索和下载（含后台弹幕配置中的「测试」） | 关闭 |

「弹幕抓取」默认关闭，原因是自建的 danmu-api 通常部署在内网，经代理转发后反而无法连接。从旧版本升级时该模块同样为关闭状态，弹幕请求保持直连；其他模块保留原有的开关设置。

示例：代理软件运行在宿主机的 `7890` 端口，需要弹弹play 官方接口通过代理访问。代理地址填写 `http://host.docker.internal:7890`（容器内的 `127.0.0.1` 指向容器自身），开启全局开关，再开启「弹幕抓取」。

## 弹幕

### 全网弹幕未显示时如何排查？

先在后台「网站配置」→「基本信息」→「弹幕系统配置」中使用「测试」按钮进行测试，再查看播放器弹幕输入框中的加载状态。

显示全网弹幕需同时满足以下条件：开启「启用弹幕系统」和「自动嗅探全网弹幕」，并已填写自建 danmu-api 地址，或已填写弹弹play 的 AppId 和 AppSecret。

**测试按钮**：开启「自动嗅探全网弹幕」后显示。输入片名并点击「测试」，系统使用当前填写的配置（无需先保存）拉取该影片第 1 集的全网弹幕，结果显示在按钮下方，例如「匹配到「葬送的芙莉莲 第1话」，第 1 集共 N 条全网弹幕」或「失败：弹幕接口请求超时」。测试不读取也不写入弹幕缓存，是否经过代理与播放页相同，取决于「网络代理」中的「弹幕抓取」开关。

**输入框中的加载状态**：弹幕加载状态显示在播放器控制条的弹幕输入框中，不遮挡画面。输入框中的灰色文字显示结果，左侧圆点表示状态；鼠标悬停在输入框或圆点上可查看完整说明（含失败原因）。播放器宽度小于 560 像素时输入框收起，圆点改为显示在弹幕开关右上角，鼠标悬停在开关上可查看完整说明；加载失败时另在画面上简短提示一次（见下一节）。

| 圆点 | 输入框灰色文字 | 含义 |
| --- | --- | --- |
| 灰色闪烁 | 弹幕加载中… | 正在拉取弹幕 |
| 绿色 | 共 N 条弹幕，说点什么吧 | 已获取本站和全网弹幕，N 为合计条数；悬停显示「已加载 N 条弹幕（全网 M 条）」 |
| 黄色 | 共 N 条弹幕，未找到全网弹幕 | 未匹配到该影片，或该集没有全网弹幕；没有任何弹幕时显示「未找到全网弹幕，说点什么吧」 |
| 红色 | 全网弹幕加载失败：原因 | 接口超时、无法连接、鉴权失败或返回内容无法解析等；文字过长时以省略号结尾，悬停可查看完整原因和本站弹幕条数 |
| 红色 | 弹幕加载失败：原因 | 获取弹幕的请求本身失败（接口返回错误或网络中断） |
| 不显示 | 共 N 条弹幕，说点什么吧 | 未开启全网弹幕，仅有本站用户发送的弹幕；没有任何弹幕时显示插件默认文字「发个友善的弹幕见证当下」 |

切换剧集时播放器重建，状态从「弹幕加载中…」重新开始。

失败原因仅包含面向用户的说明，不包含接口地址和密钥。获取到的全网弹幕按接口地址、片名和集数缓存 7 天；未匹配或失败的结果不缓存，下次播放时重试。

### 弹幕设置会保存吗？播放器变窄时会怎样？

会保存。在播放器弹幕设置中修改的开关、透明度、字号、速度、显示区域、弹幕类型和防重叠设置保存在当前浏览器中，切换剧集或再次打开时沿用。仅保存修改过的项。更换浏览器或清除网站数据后恢复默认值。

播放器按自身的显示宽度排版，不区分手机或电脑，也不读取浏览器标识：宽度相同的播放器，在手机上与在缩窄的电脑浏览器窗口中（包括开发者工具的响应式模式）表现一致。调整窗口大小、旋转屏幕、进入或退出全屏时实时切换，无需刷新页面。

| 播放器宽度 | 控制条 | 加载状态 | 顶部/底部固定弹幕 |
| --- | --- | --- | --- |
| 小于 560 像素（手机竖屏、很窄的窗口） | 收起弹幕输入框和网页全屏按钮（已处于网页全屏时保留该按钮，用于退出），缩小按钮间距 | 弹幕开关右上角的圆点，悬停在开关上查看说明；加载失败时在画面上简短提示一次 | 以滚动弹幕显示 |
| 560–767 像素（手机横屏、平板、窄窗口） | 显示输入框，宽度随控制条收窄；收起网页全屏按钮 | 输入框灰色文字和圆点 | 以滚动弹幕显示 |
| 768 像素及以上 | 完整控制条 | 输入框灰色文字和圆点 | 按原样固定在顶部/底部 |

560 像素是按钮间距缩小后输入框仍能保留约 110 像素的最小宽度，更窄时输入框只剩数十像素，发送按钮会超出播放器；768 像素与播放页切换为移动端排版的宽度一致。宽度小于 768 像素时，画面的半屏区域只有五到八行，固定弹幕会遮挡滚动弹幕，因此改为滚动弹幕，与其他弹幕一同避让。

**字号**：设置中的字号（默认 25 像素）以大尺寸播放器为基准。播放器宽度不小于 575 像素时按原值使用；更窄时按宽度等比缩小，且不超过「播放器宽度 ÷ 22」（宽度约 360 像素时不超过 16 像素），最小 12 像素。因此在电脑上调大的字号在窄播放器上不会铺满画面。在窄播放器上调整字号时，保存的是换算回大尺寸播放器的值。

**显示区域**：「1/4」「半屏」「3/4」「满屏」以画面本身为基准计算。窄屏下播放器高于画面、画面上下有黑边时，弹幕只显示在画面内，不会出现在黑边上。

播放器尺寸变化时，屏幕上正在滚动的弹幕会被清除，之后的弹幕按新尺寸重新排布，避免新旧两套行位重叠。

## 登录与权限

### 后台页面可以打开，但接口提示未登录，原因是什么？

前端只做初步检查，实际校验在后端完成：

1. `web/src/proxy.ts` 只检查 `ecohub_auth_token` cookie 是否存在。
2. 打开 `/manage` 时，服务端布局请求 `/api/manage/user/info`，后端校验 JWT 和 Redis 中保存的当前 token，失败时跳转到 `/login`。
3. 如页面打开后 token 失效（过期、被其他设备登录顶替、在 Redis 中被清除），后续接口返回未登录，前端跳转回登录页。

一切以后端返回结果为准。登录有效期为 10 天，过期后须重新登录。

### 默认账号和访客账号如何使用？

首次启动只创建超级用户 `admin`。密码取自 `ECOHUB_ADMIN_PASSWORD`，未设置时为 `admin`。`admin` 已存在时不会修改其密码。首次登录后请立即在后台修改密码。

其他账号在后台「账号管理」中创建，共有三种角色：

| 角色 | 权限 |
| --- | --- |
| 超级用户 | 全部操作，包括网站配置、账号管理和升级 |
| 普通用户 | 日常管理，不能执行仅限超级用户的操作 |
| 访客 | 只读。所有 GET 请求放行，POST / PUT / PATCH / DELETE 请求均被拒绝 |

### 开启私有化访问后订阅怎么填？

在后台「网站配置」中开启「私有化访问」时须填写订阅密钥。开启后：

- 前台和前台接口：需要登录，或携带正确的订阅密钥。
- 订阅地址（`/api/provide/app`、`/api/provide/tvbox`、`/api/provide/vod`）：必须携带订阅密钥。

密钥可通过地址参数或请求头 `X-Provide-Key` 传递。示例（密钥为 `mysecret888`）：

```text
http://<服务器IP>:3000/api/provide/tvbox?key=mysecret888
```
