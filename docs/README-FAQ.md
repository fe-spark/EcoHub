## 采集与数据

### 搭建完成后为什么看不到影片？

因为还没采集。发布镜像不带影视数据，第一次启动只写入 12 个预设采集站，不会自动跑全量采集。

到后台「采集中心」执行一次全量采集。采集站越多越慢，第一次可能要几个小时。不用等全部采完：每采完一批，这一批会刷新到前台读取的快照里，主站的影片会边采边出现。

前台列表、后台影片列表和 TVBox / MacCMS 订阅都读快照，不直接读采集中的表。所以一批都还没刷出来时，前台是空的，这是正常的。

### 主站是什么？

主站是已启用采集站里排在最前面的那一座。前台首页、分类、搜索、每日更新只展示主站自己采到的影片和分类。

举例：采集站顺序是 A、B、C，都已启用，主站就是 A。把 B 拖到最前面，前台立刻换成 B 已经采到的数据，不会重采，A 和 C 的数据也不会删。所有采集站都停用时没有主站。

播放页从主站的这部影片出发，用匹配键找到其他已启用采集站的同一部片，把它们的线路附在后面。线路按采集站分开显示。

海报源是另一个标记，不决定主站。前台封面优先用海报源里对上的同一部片的封面，对不上才用主站自己的图；海报源就是主站时直接用主站的图。

### 切换主站会清掉什么？

什么都不清。不删影片，不重采，采集进行中也可以切换。

首页轮播按采集站分开存。切换后首页展示新主站自己那组轮播，原来那组还在，切回去就能看到。

注意和下面两件事区分：

- 修改某个采集站的采集地址：会清空这一站的影片、线路、失败记录和分类（没有播放线路的影片也清），再重新拉分类。其他站不受影响。
- 删除某个采集站：同样只清这一站。

### 影片怎么去重、怎么跨站对上？

每个采集站各存一份，采集时不合并。

- 同一站内：`movie_source_mapping` 用「采集站 + 采集站给的 `vod_id`」认出这部片的旧记录，再次采集只更新这一条。同一站同一页里匹配键相同的条目合成一部。
- 不同站之间：匹配键不用来合并记录，只在播放页读取时用来找其他站的同一部。按这个顺序找：豆瓣 ID + 片名，片名 + 大类，纯片名。多个键命中同一部只算一次。线路按站分开，不会把不同站的集数拼在一起。

分类的键是 `source:{采集站 ID}:{采集站分类 ID}`，和这一站自己的分类树一一对应。

### 刮削结果和首页轮播存在哪？

- 影片刮削：直接改这部片选中的封面、简介、评分等字段。片名和分类不动。改了没有「还原」。
- 首页轮播：按采集站分开存。每条只记影片、排序，以及在后台改过的图片、简介、评分、年份；其余信息展示时从片库实时取。在轮播里刮削只写轮播这一条，不改影片本身，也没有另外的刮削表。

### 手动停止采集后，数据是什么状态？

停止会中断还在拉取的页。已经成功入库的页保留在片库里；正在写库的页会写完，还在排队等写库的页直接丢弃。失败的页记在「采集记录」里，可以重试。

## 快照与缓存

### 采集过程中为什么要刷快照？

因为前台不直接读采集中的表。采集过程中表一直在变，每采完一批就把这一批刷进快照，并按影片增量更新内存里的搜索索引。前台列表、筛选、后台影片列表和 TVBox / MacCMS 都读快照。

刷完后，列表缓存的清理有 5 秒防抖：连续很多批时不会每批都清一次 Redis，最后一批后约 5 秒统一清。

搜索索引平时只做增量更新。启动时会全量加载一次；增量更新时发现内存里没有可用的索引，也会补做一次全量重建。

### 改了配置，前台为什么没马上变？

网站配置保存后会更新 Redis 并清掉首页缓存。页面还是旧的，常见原因：

- 浏览器、CDN 或反向代理有缓存。
- 运行的不是最新的代码或镜像。

影片列表、分类、筛选只看当前主站。切换主站后立刻展示新主站已经采到的影片；新主站还没采过，就是空的。

TVBox 的常规列表另有一层 Redis 缓存，最长约 12 小时，入库后会按防抖清理。还不一致时，先核对访问的是不是同一个实例、请求参数是否一样。

### 「最近更新」按什么排序？分类页和 TVBox 一致吗？

按 `film_index.update_stamp` 从新到旧，相同时再按 `mid`。

- 新入库的影片：用采集站给的更新时间。
- 已经在库里的影片：采集时只有播放线路有变化，才把时间改成这次采集的时间。只改了下载线路、备注、演员或封面，排序不变。
- 在后台手动保存一部影片，也会把它的时间改成保存时间。

所有采集站同一套规则。

前台分类页和 TVBox 的筛选项来自同一份筛选项数据，匹配规则也一样，只是前台查内存索引、TVBox 查 MySQL：

| 筛选 | 规则 | 两边是否一致 |
| --- | --- | --- |
| 分类 | 按该站的分类规则展开成同一组源站分类（含合并组），只列有该站播放线路的影片 | 一致。前台用主站，TVBox 用订阅里每个站点自己的站 |
| 剧情 | 影片的剧情标签里包含所选值 | 一致 |
| 地区、语言 | 与所选值完全相同 | 一致 |
| 年份 | 等于所选年份；传入的不是数字时不筛 | 一致 |
| 「其他」 | 取值不在筛选项里，空值也算 | 一致 |
| 排序 | 最近更新、人气、评分、时间。按「时间」排序时，同一年份的再按更新时间排 | 一致 |

两边都有 Redis 缓存，时长不同：前台筛选结果 2 小时；TVBox 不带剧情、地区、语言、年份条件的列表页约 12 小时，带条件的 3 分钟。短时间不一致时先看缓存。

## 网络

### 哪些请求走后台「网络代理」？

只有在后台「网络代理」（`/manage/system/proxy`）开启全局代理、并且对应模块的开关也开着时，这个模块的请求才走代理；其他情况一律直连。容器的环境变量不影响出站。

| 模块（后台名称） | 管哪些请求 | 新装默认 |
| --- | --- | --- |
| 影视采集爬虫 | 采集站接口。每个采集站还要在编辑页单独打开「采集接口代理」 | 开 |
| TMDB 刮削 | 对 TMDB 接口的请求（含后台的连通测试） | 开 |
| Telegram 机器人 | 通知推送和翻页按钮的轮询 | 开 |
| 系统版本更新 | GitHub 版本检查 | 开 |
| 弹幕抓取 | 弹弹play 官方接口或自建 danmu-api 的弹幕搜索和下载（含后台弹幕配置里的「测试」） | 关 |

「弹幕抓取」默认关闭，因为自建的 danmu-api 常在内网，转到代理上反而连不上。从旧版本升级时，它也是关闭的，弹幕照旧直连；其他模块保持原来保存的开关。

例：代理软件跑在宿主机的 `7890` 端口，想让弹弹play 官方接口走代理。地址填 `http://host.docker.internal:7890`（容器里的 `127.0.0.1` 是容器自己），打开全局开关，再打开「弹幕抓取」。

## 弹幕

### 全网弹幕没出来，怎么查？

先在后台「网站配置」→「基本信息」→「弹幕系统配置」里用「测试」按钮试一次，再看播放器弹幕输入框上的加载状态。

全网弹幕要同时满足：打开「启用弹幕系统」和「自动嗅探全网弹幕」，并且填了自建 danmu-api 地址，或者填了弹弹play 的 AppId 和 AppSecret。

**测试按钮**：打开「自动嗅探全网弹幕」后出现。填一个片名，点「测试」，用当前填写的配置（可以先不保存）拉这部片第 1 集的全网弹幕，结果直接显示在按钮下面，例如「匹配到「葬送的芙莉莲 第1话」，第 1 集共 N 条全网弹幕」或「失败：弹幕接口请求超时」。测试不读也不写弹幕缓存，走不走代理和播放页一样，看「网络代理」里的「弹幕抓取」开关。

**输入框上的加载状态**：弹幕加载状态显示在播放器控制条的弹幕输入框上，不盖在画面上。输入框里的灰字给出结果，左侧小圆点表示状态，鼠标停在输入框或圆点上可以看完整说明（含失败原因）。

| 圆点 | 输入框灰字 | 意思 |
| --- | --- | --- |
| 灰色闪烁 | 弹幕加载中… | 正在拉取弹幕 |
| 绿色 | 共 N 条弹幕，说点什么吧 | 本站和全网弹幕都拿到了，N 是合计；悬停显示「已加载 N 条弹幕（全网 M 条）」 |
| 黄色 | 共 N 条弹幕，未找到全网弹幕 | 没匹配到这部片，或这一集没有全网弹幕；一条弹幕都没有时显示「未找到全网弹幕，说点什么吧」 |
| 红色 | 全网弹幕加载失败：原因 | 接口超时、连不上、鉴权失败、返回内容无法解析等；放不下时以省略号结尾，悬停看完整原因和本站条数 |
| 红色 | 弹幕加载失败：原因 | 获取弹幕的请求本身失败（接口返回错误或网络中断） |
| 不显示 | 共 N 条弹幕，说点什么吧 | 没开全网弹幕，只有本站用户发的弹幕；一条都没有时是插件默认的「发个友善的弹幕见证当下」 |

换集时播放器重建，状态从「弹幕加载中…」重新开始。

失败原因只写给人看的说明，不包含接口地址和密钥。拿到的全网弹幕按接口地址、片名、集数缓存 7 天；没匹配到或失败的结果不缓存，下次播放会重试。

### 弹幕设置会保存吗？手机上为什么没有输入框？

会保存。在播放器弹幕设置里改的开关、透明度、字号、速度、显示区域、弹幕类型和防重叠，存在当前浏览器里，换集或下次打开时沿用。只存你改过的项。字号在手机和电脑上分开存：手机不沿用电脑上的字号。换浏览器或清掉网站数据后恢复默认。

手机上（按浏览器标识识别为 iPhone、iPad、iPod、Android，或窗口宽度不超过 768 像素）只保留弹幕开关和设置，不显示输入框，所以手机上不能发弹幕。手机上看不到输入框上的加载状态，弹幕加载失败时会在画面上简短提示一次原因，其他状态不提示。

手机上的弹幕字号默认是播放器高度的 8%（竖屏约 15px，横屏全屏时跟着变大），在设置里调过字号就用你调的。顶部和底部固定弹幕在手机上一律按滚动弹幕显示，和滚动弹幕一起避让，不会互相压住。

## 登录与权限

### 后台页面能打开，接口却提示未登录？

前端只粗查了一下，真正的校验在后端：

1. `web/src/proxy.ts` 只看 `ecohub_auth_token` cookie 在不在。
2. 打开 `/manage` 时，服务端布局会请求 `/api/manage/user/info`，后端校验 JWT 和 Redis 里存的当前 token，失败就跳 `/login`。
3. 页面打开以后，token 才失效（过期、被别的设备登录顶掉、Redis 里被清掉），之后的接口会返回未登录，前端跳回登录页。

一切以后端返回为准。登录有效期是 10 天，过期后要重新登录。

### 默认账号和访客账号怎么用？

第一次启动只创建超级用户 `admin`。密码取 `ECOHUB_ADMIN_PASSWORD`，没设就是 `admin`。`admin` 已存在时不会改它的密码。登录后马上在后台改密码。

其他账号在后台「账号管理」新建，角色有三种：

| 角色 | 能做什么 |
| --- | --- |
| 超级用户 | 全部操作，包括网站配置、账号管理、升级 |
| 普通用户 | 日常管理，但不能做只限超级用户的操作 |
| 访客 | 只能看。所有 GET 请求放行，POST / PUT / PATCH / DELETE 都被拒绝 |

### 开启私有化访问后订阅怎么填？

在后台「网站配置」打开「私有化访问」时要填订阅密钥。打开之后：

- 前台和前台接口：要登录，或者带上正确的订阅密钥。
- 订阅地址（`/api/provide/app`、`/api/provide/tvbox`、`/api/provide/vod`）：必须带订阅密钥。

密钥可以放在地址参数里，也可以放在请求头 `X-Provide-Key` 里。例如密钥是 `mysecret888`：

```text
http://<服务器IP>:3000/api/provide/tvbox?key=mysecret888
```
