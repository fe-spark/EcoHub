# 常见问题

中文 | [English](./README-FAQ_EN.md)

## 采集与数据

### 搭建完成后为什么看不到影片？

发行镜像不包含影视数据。首次启动会写入默认采集源，但不会自动跑完采集。须在管理后台执行采集；首次全量可能持续数小时，源站越多耗时越长。

前台、后台影片列表以及 TVBox / MacCMS 都读取快照 / 内存读模型，而不是采集过程中的业务表。入库成功的页会按窗口刷进快照，首选站影片边采边出现在前台；尚未刷出任何快照时表现为空站，属预期行为。

### 主站和附属站如何分工？为什么必须有主站？

主站写入影片主数据（`film_index`、详情、检索入口）。附属站只写入播放列表，详情页与播放页将附属源聚合到已匹配的主站影片下。后台支持对同一影片执行「更新全部站点」。

没有主站时，播放列表无处挂载，分类树也不会从附属站构建。任意时刻只允许一个主站；新增或升级主站会将旧主站降级。

### 切换主站后为什么要重建数据？

主站决定影片基础信息、分类和搜索入口。切换主站、变更主站 URI 或将主站降级时，会停止采集并清理该主站主数据，再用新主站重新整理，避免新旧分类、详情和列表混杂。附属站播放列表会保留，待新主站全量采集后重新匹配。

### 影片如何去重、如何跨站对齐？

这是两套键，不是「一律按豆瓣 ID 合并」：

- **站内身份**：一部片子一个 `film_index.mid`。同一采集站的 `vod_id` 通过 `movie_source_mapping` 绑到这个 mid。
- **跨站匹配**（`movie_match_key`）：优先「豆瓣 ID + 规范化片名」，豆瓣相同但片名不同不算同一部；片名会去掉更新至/完结/语种/清晰度等片尾噪音，但保留剧场版、3D、动态漫画等版本。否则规范化片名#大类，再保留纯片名回退。分类是 `film_index.pid` / `cid` 上的独立字段，**不编进 mid**；匹配键带大类是为了拆开同名跨类（例如「仙逆」短剧已完结、「仙逆」动漫还在更新）。

**播放源怎么绑**：附属站规范化片名与主站全等才考虑绑定。豆瓣 ID、年份、导演、剧集结构在**两边都有值且对不上**时一票否决；任一边空或未知不否决。否决后主站只剩一部这个名字 → 直接绑。主站有多部同名 → 依次看豆瓣 ID、大类、年份（同年，其次差 1 年）是否只对上一部；对不上就不绑。已经绑上的源详情页直接展示，不再用线路结构二次过滤。

**同名跨类为什么要隔离**：每日更新看的是 `update_stamp`，抬 stamp 的条件是本源集数严格大于该片全库已有最大集数。两部同名片若共用一把纯片名键，完结短剧的集数会算进连载动漫，动漫再追一集也进不了每日更新。

**主站与附属站的采集顺序不受限制**：附属站片名只对上一部主站影片、且未被否决时，播放列表写到该片已有主键（分类标错也绑）。主站已有多部同名片时，再按豆瓣 / 大类 / 年份选一部；选不出就不绑，按副站自己的候选键落库。有大类时不写纯片名键。

### 手动停止采集后数据处于什么状态？

停止会中断仍在拉页的任务，并取消对应 context。已经成功入库的页留在 `film_index`；失败页进入重试队列。收尾只冲掉剩余发布缓冲。

## 快照与缓存

### 采集过程中为什么要刷快照？窗口发布为何仍可能耗时？

采集过程中库表持续变化。每窗刷新本批播放摘要，并按 mid 增量更新内存检索索引。前台列表、筛选、后台影片列表和 TVBox / MacCMS 都读 `film_index`。

列表缓存约 5 秒防抖，避免每页清 Redis。检索全量重建只在启动时分页加载。

### 修改配置后前台为什么没有立刻变化？

网站配置写入后会更新 Redis 并清理首页缓存。若页面仍旧，常见原因是浏览器、CDN 或反向代理缓存，或当前进程不是最新代码。

影片列表、分类、筛选取决于 `film_index`，并锁定首选站。改采集源不会填满前台，要等该源（尤其是新的首选站）采集入库。TVBox 常规列表另有 Redis 缓存（最长约 12 小时），入库后会按防抖清理；若仍不一致，优先核对运行实例与请求参数。

### 「最近更新」按什么排序？分类页和 TVBox 是否一致？

最近更新按快照里的 `update_stamp` 降序（同分再按 `mid`）。该字段不是「任意主站字段一变就刷新」：

- 主站：新片，或分集数量严格增加时才刷新。备注、演员、封面等不顶排序。
- 附属站：仅当已匹配到主站影片、且本源分集数量严格大于该片历史最大集数时才刷新为当前时间。只补线路、改链接，或最后一集标签变了但集数未增加，不改变该排序。附属站首次挂上主站影片时沿用主站原有 stamp。

前台分类筛选与 TVBox 走同一套读模型规则（分类、剧情 / 地区 / 语言 / 年份、排序）。TVBox 常规列表多一层 Redis 缓存，因此短时间不一致时先看缓存。

## 登录与权限

### 后台页面能打开，接口却提示未登录？

边缘中间件只检查 `ecohub_auth_token` cookie 是否存在。打开 `/manage` 时，服务端 layout 还会请求 `/api/manage/user/info`，由后端校验 JWT 与 Redis token；失败会跳转 `/login`。已经打开的后台页在 token 事后失效（过期、被其它设备顶掉、Redis 中已失效）时，后续接口仍可能返回未登录。以后端返回为准。

### 访客账号与默认账号如何使用？

初始化只创建超级管理员 `admin` / `admin`。普通用户和访客在账号管理中新建。访客可调用管理端 GET；POST / PUT / PATCH / DELETE 会被 `WriteAccess` 拒绝。对外部署后须立即修改默认密码。
