# 常见问题

中文 | [English](./README-FAQ_EN.md)

## 采集与数据

### 搭建完成后为什么看不到影片？

发行镜像不包含影视数据。首次启动会写入默认采集源，但不会自动跑完采集。须在管理后台执行采集；首次全量可能持续数小时，源站越多耗时越长。

前台、后台影片列表以及 TVBox / MacCMS 都读取采集结束后发布的快照 / 内存读模型，而不是采集过程中的库表。快照未发布前表现为空站，属预期行为。

### 主站和附属站如何分工？为什么必须有主站？

主站写入影片主数据（`film_index`、详情、检索入口）。附属站只写入播放列表，详情页与播放页将附属源聚合到已匹配的主站影片下。后台支持对同一影片执行「更新全部站点」。

没有主站时，播放列表无处挂载，分类树也不会从附属站构建。任意时刻只允许一个主站；新增或升级主站会将旧主站降级。

### 切换主站后为什么要重建数据？

主站决定影片基础信息、分类和搜索入口。切换主站、变更主站 URI 或将主站降级时，会停止采集并清理该主站主数据，再用新主站重新整理，避免新旧分类、详情和列表混杂。附属站播放列表会保留，待新主站全量采集后重新匹配。

### 影片如何去重、如何跨站对齐？

这是两套键，不是「一律按豆瓣 ID 合并」：

- **主站身份**（`film_index.content_key`）：有源站 `vod_id` 时为 `vod_{id}`，否则回退片名哈希。同一主站上不同 `vod_id` 会写成两条，即使片名或豆瓣 ID 相同。
- **跨站匹配**（`movie_match_key`）：附属站用来挂到主站影片。优先豆瓣身份（含标题中的季/段），否则规范化片名。同一匹配键命中多部时，取 `update_stamp` 较新者。

### 手动停止采集后数据处于什么状态？

停止会中断仍在拉页的任务，并取消对应 context。已经 `page_done` / `waiting_publish` 的站点仍会进入收尾发布。

主站**全量**采集在出错或被停止时**不会**把本次待发布的 mid 写入快照（会丢弃 pending，跳过发布）。库中可能已有部分写入，但前台读模型保持上一版快照。主站增量或附属站在已有写入的情况下，仍会收尾并发布该部分增量。

## 快照与缓存

### 采集结束后为什么还要发布快照？增量发布为何仍可能耗时？

采集过程中库表持续变化。收尾阶段会刷新播放摘要、发布列表快照并切换内存读模型。前台列表、筛选、后台影片列表和 TVBox / MacCMS 均读取该结果。

增量发布仍须处理受影响的 mid：写快照、重建筛选项、加载读模型。影片量大时，数据库写入和内存读模型都会占用时间和内存。读模型按片库常驻内存，不是发布瞬间才出现、随后立刻释放。

### 修改配置后前台为什么没有立刻变化？

网站配置写入后会更新 Redis 并清理首页缓存。若页面仍旧，常见原因是浏览器、CDN 或反向代理缓存，或当前进程不是最新代码。

影片列表、分类、筛选取决于快照 / 读模型；采集未完成或快照未发布时，改采集源不会让前台立刻出片。TVBox 常规列表另有 Redis 缓存（最长约 12 小时），发布后会清理；若仍不一致，优先核对运行实例与请求参数。

### 「最近更新」按什么排序？分类页和 TVBox 是否一致？

最近更新按快照里的 `update_stamp` 降序（同分再按 `mid`）。该字段不是「任意主站字段一变就刷新」：

- 主站：新片，或分集数量严格增加时才刷新。备注、演员、封面等不顶排序。
- 附属站：仅当已匹配到主站影片、且本源分集数量严格大于该片历史最大集数时才刷新为当前时间。只补线路、改链接，或最后一集标签变了但集数未增加，不改变该排序。附属站首次挂上主站影片时沿用主站原有 stamp。

前台分类筛选与 TVBox 走同一套读模型规则（分类、剧情 / 地区 / 语言 / 年份、排序）。TVBox 常规列表多一层 Redis 缓存，因此短时间不一致时先看缓存。

## 登录与权限

### 后台页面能打开，接口却提示未登录？

边缘中间件只检查 `ecohub_auth_token` cookie 是否存在。打开 `/manage` 时，服务端 layout 还会请求 `/api/manage/user/info`，由后端校验 JWT 与 Redis token；失败会跳转 `/login`。已经打开的后台页在 token 事后失效（过期、被其它设备顶掉、Redis 中已失效）时，后续接口仍可能返回未登录。以后端返回为准。

### 访客账号与默认账号如何使用？

内置账号：`admin` / `admin`（可读写），`guest` / `guest`（访客）。访客可调用管理端 GET；POST / PUT / PATCH / DELETE 会被 `WriteAccess` 拒绝。默认账号仅用于初始化与演示，对外部署后须立即修改密码。
